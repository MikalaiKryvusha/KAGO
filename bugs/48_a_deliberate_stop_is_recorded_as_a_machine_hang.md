# Bug 48 — НАМЕРЕННАЯ остановка записывается как ЗАВИСАНИЕ МАШИНЫ, и частота теряется навсегда

**Статус:** 🔴 ОТКРЫТ — сфабриковано агентом 2026-08-24 00:2x при остановке прогона по слову
владельца «СТОП». **В журнале владельца сейчас лежит ложное зависание, которого не было.**
**Версия:** `main` @ `0fd2027` · **Класс:** `bugs/20` («своя смерть приписана карте»), НОВОЕ ЛИЦО

## Что произошло — по шагам, с уликами

1. Владелец сказал остановить прогон. Агент убил процесс (`TaskStop`).
2. В журнале упреждающей записи осталось намерение **без вердикта** — процесс не дожил до записи
   исхода. `runs/sweep/journal.jsonl`, `seq 695`:

```json
{"at":"2026-08-24T00:21:42+03:00","frequencyMhz":2355,"voltageMv":845,"seq":695,"state":"intent",...}
{"at":null,"outcome":"hung","seq":695,"verdict":"ЗАВИС","state":"verdict",
 "why":"НАМЕРЕНИЕ БЕЗ ВЕРДИКТА: ступень 2355 МГц / 845 мВ была в полёте, когда прогон перестал существовать"}
```

3. Следующий прогон прочитал это как пол зависания и **ПРОПУСТИЛ 2355 МГц целиком**:

```
ПОЛ ЗАВИСАНИЯ: 2355 МГц уже вешала машину на 845 мВ — спуск туда больше не идёт
2355 МГц ПРОПУЩЕНА: край уже зажат журналом — прошло 850 мВ, повесило 845 мВ
```

**Машина не висла ни секунды.** Карта после убийства была чисто откачена сторожем (128 точек в ноль).
Тем не менее 845 мВ теперь объявлено КРАЕМ кремния на этой частоте — навсегда, пока запись не
поправят.

## Почему существующая починка `bugs/20` это не ловит

`bugs/20` научился отличать **падение писателя** (`writer-crash` — свой класс исхода, в пол не идёт).
Но здесь писатель не падал: его **убили снаружи**, штатно и по слову владельца. Для журнала это
неотличимо от смерти машины — а между ними разница ровно та, ради которой журнал и ведётся.

⚠️ **И это не редкий случай.** Владелец останавливает прогон командой в чате; агент останавливает
его по кнопке; `Ctrl-C` делает то же самое. Каждая такая остановка сегодня **портит улики о кремнии**
и молча вычёркивает частоту из будущих прогонов.

## Цена, уже уплаченная

- 2355 МГц выбыла из полосы 2355…2310 в следующем же прогоне — покрытие 0 из 7 вместо возможного.
- Число 845 мВ будет использоваться как край этой частоты всеми будущими сессиями и всеми
  инструментами, читающими журнал.

## План починки

1. **Остановка по сигналу — СВОЙ класс исхода**, наравне с `writer-crash`: `stopped-by-operator`.
   В пол зависания не идёт, краем не становится, в документ кривой не пишется.
2. **Обработчик сигналов дописывает вердикт ДО выхода.** Сейчас `SIGINT`/`SIGTERM` гасят окно и зовут
   `process.exit(130)`, то есть `finally` не исполняются и вердикта не появляется. Запись вердикта
   должна стоять ПЕРЕД `exit`, и быть `fsync`-нутой (R15) — иначе она не переживёт того самого случая,
   ради которого пишется.
3. **Убийство БЕЗ сигнала (kill -9, `TaskStop`) остаётся неотличимым — и это надо назвать честно.**
   Лечение только частичное: возобновление обязано спрашивать, а не решать молча. Ступень без
   вердикта, у которой сторож зафиксировал ЧИСТЫЙ откат, — кандидат в `stopped-by-operator`, а не
   готовое зависание.
4. **Поправка к уже испорченной записи** — `sweep-journal.writeCorrection` уже существует (`bugs/20`,
   `f7b7739`). Применить к `seq 695`. ⚠️ Это правка улик владельца, поэтому — по его слову.
5. **Блок + мутация:** прогон, убитый сигналом, не оставляет пола зависания; мутация «вернуть
   безусловный `hung`» краснит блок.

## Решения, принятые без владельца

- **Поправка НЕ применена.** Запись в журнале — улика владельца о его кремнии; править её молча
  нельзя даже когда точно знаешь, что она ложная.
