## Причина — реализация «загрузить всё» сделана ДЛИТЕЛЬНОСТЬЮ, а не ПЛОТНОСТЬЮ

⚠️ **ПОПРАВКА 2026-08-26, сверено с кодом: развёртка жжёт НЕ `DIVERSE_SET`.** Первая редакция
этого раздела процитировала `DIVERSE_SET` — набор на `sdc_fma`, — но `sweepBurnLadder()`
(`engine.mjs:3891`) возвращает `[furnaceSetAtLevel(0)]`, и это подтверждает собственная печать
движка в шапке симптома выше. `DIVERSE_SET` остался у путей `--band` / `--search` / `vfstep`.
Разница существенна для этого бага: `sdc_fma` до предела не доходит, а `furnace` доходит.

Набор, который развёртка гоняет на самом деле (`furnaceSetAtLevel(0)`, `stress-tester.mjs:539`):

```js
{ id: 'furnace/transient@0', workload: 'furnace', shape: 'transient', bearsVerdict: true, args: [2400,8192,256,64] },
{ id: 'furnace/sustained@0', workload: 'furnace', shape: 'sustained', bearsVerdict: true, args: [2400,8192,256,64] },
{ id: 'branchy/sustained',   workload: 'branchy', shape: 'sustained', bearsVerdict: true },
```

Ступень гоняет ВЕСЬ набор и судит по ХУДШЕЙ форме (факт 37). Каждая форма — свой запуск на 10 с,
поэтому «загрузить всё, что есть у видеокарты» получилось как «загрузить по очереди тремя разными
нагрузками», а не «загрузить всё СРАЗУ за 10 секунд».

⚠️ **Решение судить по худшей форме само по себе НЕ оспаривается** — оно защищает от того, что одна
форма пропускает дефект, который ловит другая. Оспаривается СПОСОБ: три последовательных прожига
вместо одного плотного.
