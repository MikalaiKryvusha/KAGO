## Gap

Every KAIF instrument optimizes a LOCAL invariant: `/fable-judge` verifies that claims match
observations; `TESTING_FRAMEWORK` verifies artifacts; guards verify safety; `/check-backlog` counts
open vs DONE. **No instrument anywhere asks whether the work moved the project toward the owner's
acceptance criterion.** Loops pick "ANY task from the backlog"; `/what-next` ranks by value in
prose; a session can close VERIFIED, honest, green — and have moved the product zero.

An agent under this framework therefore optimizes the newest pain, at full ceremony, indefinitely.
The framework rewards it: every local invariant is satisfied.

## Proposed change

1. **The delivery line.** The project canon names ONE machine-readable acceptance metric (in
   `GOAL.md`/`MASTER_PLAN.md`). Every loop iteration and every session close MUST print it:
   `<metric>: X → Y this session; moved by: <one line / or the named blocker>`. A forced artifact at
   a decision point — the form issue #22 proved models actually follow.
2. **A judge hunt.** `/fable-judge` treats a session report without the delivery line — or with a
   zero delta and no named blocker — as a finding of the false-completion family.
3. **Grooming by the denominator.** `/what-next` and the loop skills rank candidate work FIRST by
   «does it move the metric or unblock the next scarce-resource run», and only then by the
   Eisenhower matrix. The newest pain is explicitly NOT a priority claim.
