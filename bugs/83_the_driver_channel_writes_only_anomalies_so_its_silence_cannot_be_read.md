# Bug 83 — канал драйвера пишет только аномалии, поэтому его молчание нечитаемо

**Статус:** 🔴 ОТКРЫТО — найден шагом 3.8 плана `plans/74` (фаза 3 эпика 76).
**Версия:** `main` @ `1e1a5f2` · **Где:** `automation-engine/lib/death-watch.mjs` → `runWatcher`
**Карта не нужна:** разбирается чтением кода и записанным журналом инцидента.

## Симптом — четыре минуты молчания, которые нельзя истолковать

`bugs/76`: перед смертью машины 30 августа файл `…-driver.jsonl` молчал около четырёх минут.
Вопрос шага 3.8 был поставлен так: он молчал законно или терял записи?

**Ответ: молчал законно.** Строка пишется только когда `verdict.record` — то есть когда промах
такта превысил `RECORD_THRESHOLD_MS = 10` мс. Каждая такая строка честно `fsync`-ается, и
комментарий у места это прямо объясняет: *«a machine death takes the page cache with it; the line
must not»*. Записи не терялись — их не было.

🔴 **И ровно поэтому канал бесполезен для разбора.** Журнал, пишущий только аномалии, **не отличает
«аномалий не было» от «проба умерла»**. В те 110 секунд между первым криком `nvlddmkm` и смертью
машины его молчание означало одно из двух, и разбор не может сказать, какое.

Это тот же класс, что убил кольцо судьи (`bugs/78`): **улика существует только в момент, когда
что-то пошло не так, а вопрос разбора — «а был ли вообще кто-то жив».** Итоговая сводка
(`ПРОБА ЗАКОНЧИЛА: тактов N/M`) печатается при ШТАТНОМ выходе, то есть ровно тогда, когда она не
нужна: зависание штатного выхода не даёт.

## Repro

Не нужен прогон: свойство следует из кода.

```js
// death-watch.mjs → runWatcher
const verdict = classifyTick({ promisedMs, actualMs: wokeMs, callMs, recordThresholdMs });
if (verdict.record) {                       // ← единственное условие записи
  writeSync(fd, formatMiss({ ... }));
  fsyncSync(fd);
}
```

Здоровая проба, ни одного промаха > 10 мс → файл пуст. Мёртвая проба → файл пуст. Различить нечем.

## Корневая причина

Канал спроектирован как журнал СОБЫТИЙ (промахов), а разбор задаёт ему вопрос о СОСТОЯНИИ (жила ли
проба). Для журнала событий отсутствие записей — законный и ожидаемый режим; для вопроса о
состоянии — неразличимая двусмысленность. Порог 10 мс здесь ни при чём: при любом пороге молчание
остаётся двузначным.

## План починки — то же лекарство, что у судьи

Периодическая строка жизни, как в `@forensic fuse-alive` (`bugs/78`, сделано этой же ночью):
раз в секунду одна строка с немедленным `fsync`, несущая число тактов за окно и худший промах.
Тогда пустое окно означает «проба мертва», а не «всё хорошо».

1. Аккумулятор в том же такте, без второго таймера.
2. Строка в `…-driver-alive.jsonl` (отдельный файл — журнал промахов не смешивается с журналом
   жизни, у них разные читатели).
3. Маркер `@forensic` с `DURABLE-AT: every-second` и честным полем `GAP` про то, что `fsync` на
   стенде недоказуем (`taskkill` убивает процесс, а не ОС — тот же зазор, что у `fuse-alive`).
4. Блок, доказанный КРАСНЫМ на сегодняшнем коде, — по образцу C1 из `fuse.mjs`.
5. Замер скорости пробы до/после **тремя прогонами с каждой стороны**: собственный разброс прибора
   больше искомого эффекта, и парой одиночных прогонов вопрос не решается (урок шага 3.6).

## Почему НЕ сделано сразу

«Одна фаза — один предмет» (риск «в» плана `plans/74`). Фаза 3 эпика 76 закрывает долговечность
улики СУДЬИ; проба — отдельный процесс, отдельный файл, отдельный замер скорости. Смешивать —
значит закрывать фазу утверждением вместо измерения.

## Решения, принятые без владельца

- **Отдельный файл `…-driver-alive.jsonl`, а не строки жизни в общий журнал промахов** — у журнала
  событий и журнала состояния разные читатели, и смешение заставило бы разбор фильтровать улику.
