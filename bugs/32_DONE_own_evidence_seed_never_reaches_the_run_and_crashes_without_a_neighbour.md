# Bug 32 — собственная улика частоты не доезжает до прогона, а без соседки роняет развёртку

**Status:** ✅ DONE
**Version/build:** `HEAD` = `c4d12f8` · **When/context:** найден 2026-08-23 09:5x +03:00 при
исполнении `plans/25` шаг 1.2 — блок самопроверки, написанный на новый шов `bugs/31`, УПАЛ на первом
же прогоне. Дефект внесён 2026-08-22 коммитом `9b7855f` (та самая починка `bugs/31`).

## Symptom

`planFrequency` выбирает затравку как ГЛУБОЧАЙШУЮ из двух улик — собственной (`provenPassMv`,
журнал этой частоты) и соседкиной (`seedFor`). Решение кладётся в `plan.seedMv`.

`sweepFrequency` этого решения НЕ ЧИТАЕТ. Он берёт `plan.seed.seedMv` — сырое значение соседки.
Отсюда два лица одного дефекта:

**(а) Прогон заказывает НЕ ТО напряжение, которое напечатал план.** Замерено пробой на
`planFrequency`, 2026-08-23:

```
план решил стартовать с            : 870 мВ
источник назван собственным        : true
а прогон закажет (plan.seed.seedMv): 990 мВ — от соседки 2850 МГц
РАСХОЖДЕНИЕ                        : ЕСТЬ
```

То есть **починка `bugs/31` инертна на пути прогона.** Экономия ступеней, ради которой она делалась,
не наступает: спуск начинается со 990 и заново жжёт всё, что частота уже доказала. Владелец видел
ровно это: *«край найден у точки, какого хуя вновь с неё начинать не понимаю и злюсь»* — и после
починки увидел бы то же самое.

**(б) Без соседки развёртка ПАДАЕТ.** Когда `seedFor` возвращает `null` (в документе нет оттюненной
соседки), а собственная улика есть, `plan.seedMv` не `null`, и строка 1590 разыменовывает `null`:

```
TypeError: Cannot read properties of null (reading 'seedMv')
    at sweepFrequency (engine.mjs:1590:37)
    at sweepRange (engine.mjs:2081:27)
```

Это не теоретический случай: он наступает на ПЕРВОЙ частоте возобновляемого прогона, когда выше по
диапазону ещё ничего не оттюнено, — то есть в самом начале полосы.

## Repro (deterministic)

Офлайн, без карты. Блок `ЗАЖАТЫЙ КРАЙ НЕ ЖГЁТСЯ ЗАНОВО` в `engine --selftest` (документ из одной
строки 2842 МГц + журнал с PASS и ЗАВИС) воспроизводит (б) падением всего набора.
Лицо (а) воспроизводится вызовом `planFrequency` с `provenPassMv: 870` при соседке на 990 мВ и
сравнением `p.seedMv` с `p.seed.seedMv`.

## Root cause

**Пара «истина↔зеркало» внутри одной функции — ровно тот класс, который проект уже оплачивал
(EXP-0077).** Решение о затравке было ОДНО (`plan.seedMv`), а мест, называющих её значение, стало
два: план и `sweepFrequency`. Правило R16c требует обратного — план и прогон обязаны быть ОДНИМ
вычислением, и `bugs/09` заведён ровно на цену расхождения: сухой прогон это документ, который
оператор читает ПЕРЕД разрешением на запись в карту владельца.

Почему не покраснело при внесении: `provenPassMv` и `preBracketed` вышли в бой без единого блока —
замерено 2026-08-23, мутации «не читать собственную улику» и «убрать пропуск зажатой частоты»
оставляли всю батарею зелёной, 959 блоков из 959.

## Fix plan

1. `sweepFrequency` берёт напряжение затравки ИЗ `plan.seedMv`, а `plan.seed` использует только для
   ИМЕНИ соседки в сообщениях — и только когда он есть.
2. Свидетель и события (`seed-accepted` / `seed-rejected` / `lever-limited`) называют источник по
   `plan.seedFromOwnEvidence`: «собственная улика этой частоты» либо «соседка N МГц». Строка
   «затравка 870 мВ от соседки 2835 МГц» там, где 870 пришли из своего журнала, — ложь в свидетеле.
3. `seedOutcome` получает `neighbourMhz: null` для собственной улики — и обязан это пережить.
4. Блоки: прогон заказывает РОВНО то, что напечатал план · развёртка без соседки не падает ·
   свидетель называет источник честно. Мутации — в шапке набора, до прогона.

## ✅ STATUS: DONE (2026-08-23 10:0x +03:00)

**Починено.** `sweepFrequency` берёт напряжение затравки из `plan.seedMv` — решения, которое план уже
принял, — а `plan.seed` использует только для ИМЕНИ соседки и только когда он есть. Источник улики
стал полем (`out.seedFromOwnEvidence`), и его читают свидетель строки, события окна и `seedOutcome`.

**Обход близнецов (`TWINS`).** Искал `seed.seedMv` / `seed.neighbourMhz` без защиты по всему дереву
(`automation-engine/**`, `tools/**`) — **найдено ЕЩЁ ДВА сайта того же класса**, оба нашлись не
чтением, а падением набора:

| сайт | что делал |
|---|---|
| `sweepFrequency` (заказ ступени, `seedOutcome`, свидетель «предел рычага») | брал сырое значение соседки, падал без неё |
| `planFrequency` → `why` отменённой затравки | приписывал соседке число, которое могло прийти из своей улики; падал при `seed === null` |
| `sweepDryRunLines` → печать отменённой затравки | то же самое в документе рельса S2 |

Отменённая затравка теперь несёт своё число полем `cancelledSeedMv`, а не берётся у соседки.

**Доказано красным, а не чтением.** Блоки в `engine --selftest`: «ПРОГОН ЗАКАЗЫВАЕТ ЗАТРАВКУ ПЛАНА» ·
«БЕЗ СОСЕДКИ РАЗВЁРТКА НЕ ПАДАЕТ» · «СВИДЕТЕЛЬ НАЗЫВАЕТ ИСТОЧНИК УЛИКИ». Мутации CQ (вернуть заказ
по `plan.seed.seedMv`), CR (разыменовать `plan.seed` без проверки), CS (приписать собственную улику
соседке) — каждая покраснила свои блоки, сводная строка на месте, код выхода 1.

**Наблюдение на настоящем журнале.** Сухой прогон полосы 2820…2790 (только чтение, журнала не
открывает): все три частоты берут затравку из собственных улик, 2820 МГц идёт **2 ступени от 870 мВ**
вместо 14 от стока. Репетиция на виртуальной карте — 5 частот из 5, покрытие 100 %.

⚠️ **Чего это НЕ доказывает:** живого прогона на карте после починки не было. Доказана ЛОГИКА
композитора (R16a — движок решает, но не пишет), а не поведение кремния.

## Decisions made without the owner

1. **Источник улики стал полем, а не прозой** (`out.seedFromOwnEvidence`). Альтернатива —
   разбирать текст свидетеля — это пара «истина↔зеркало», которую проект уже оплачивал.
2. **Отменённая затравка получила своё поле `cancelledSeedMv`** вместо чтения `p.seed.seedMv` в
   печати. Причина та же: печать не должна переспрашивать то, что план решил.
3. **Блоки ловят падение и превращают его в красный блок** (`try/catch` вокруг прогона в фикстуре) —
   по EXP-0040: мутация обязана красить блок, а не убивать отчёт. Замерено: без этого мутация CR
   уносила весь набор, и «набор не дошёл до конца» читалось как «ничего не найдено».
