**Статус:** ✅ **ЗАКРЫТ 2026-09-05 (сессия 85) — И ПРИ ПОЧИНКЕ НАШЛАСЬ ВТОРАЯ НАХОДКА, ОПАСНЕЕ

## Симптом

`interviews/026` несёт вопросы с заголовками **Q1**, **Q3**, **Q4** (Q2 был снят с владельца и
заменён разбором на своём месте). Владелец ответил на два. Файл решения
`interviews/decisions/interview_026_*.decision.json` записал их так:

```json
"answers": {
  "Q2": { "choice": "A", "comment": "частота, которая была ЗДОРОВА, но медленно запускалась…" },
  "Q3": { "choice": "A", "comment": "все перемерить. Но в понедельник. не сегодня." }
}
```

**Ключ `Q2` — это ответ на вопрос, который в документе называется `Q3`; ключ `Q3` — на `Q4`.** Ключи
проставлены ПО ПОРЯДКУ следования вопросов (второй и третий по счёту), а не по их собственным
заголовкам.

## Почему это опасно, а не косметика

Это ровно тот дефект, ради которого контур и существует: он записывает решение владельца машинно,
чтобы следующая сессия исполнила его без пересказа. Сессия с пустым контекстом, открывшая файл
решения, исполнит ответ «A» не на тот вопрос — и сделает это уверенно, потому что источник машинный.

**Я сам чуть не прочёл его неверно** и удержался только потому, что пошёл сверять с самим документом
(`grep` по полям «Ответ:»): в документе ответы легли ПРАВИЛЬНО — на строках 127 и 179, под своими
вопросами. То есть врёт не запись в документ, а именно JSON, который читают машины.

Цена ошибки здесь названа владельцем в этой же сессии: один из двух ответов — приказ, роняющий
метрику приёмки с 11 краёв до 4. Исполнить его «не тем вопросом» — испортить документ кривой.

## Улики

- `interviews/interview_026_the_fuse_returns_to_post_and_the_rows_burned_without_it.md` — заголовки
  `## Q1.`, `## Q3.`, `## Q4.` (плюс снятый `## ~~Q2~~ — СНЯТ С ВАС`, не вопрос).
- `interviews/decisions/interview_026_*.decision.json` — ключи `Q2`, `Q3`; поле `written: ["Q3","Q2"]`.
- Вставка в документ прошла верно: `**Ответ:** A` стоит под своим вопросом в обоих случаях.

## Гипотеза о причине (не проверена чтением кода — это следующий шаг)

Разбор в `tools/lib/review-core.mjs` присваивает вопросу порядковый ярлык `Q<i>` вместо того, чтобы
брать номер из его собственного заголовка. Пока нумерация в документе сплошная (Q1, Q2, Q3…), порядок
и заголовок совпадают, и дефект невидим. Он проявляется ровно тогда, когда нумерация в документе
**разрывается** — а разрывается она законно: снятый вопрос остаётся на месте разбором, и это
предписанное поведение (вопрос, снятый агентом, не удаляется, а объясняется).

## План починки

1. Прочитать разбор заголовков в `review-core.mjs` и подтвердить гипотезу цитатой строки — до правки.
2. Ярлык берётся из ЗАГОЛОВКА вопроса, а не из его порядка.
3. Сторож: фикстура-документ с разорванной нумерацией (Q1, Q3, Q4) — ключи записи обязаны быть
   `Q1`, `Q3`, `Q4`. Красный до починки, зелёный после.
4. Поправить уже записанный `interview_026_*.decision.json` — переименовать ключи под настоящие
   вопросы, с пометкой о поправке внутри файла (оригинал цел в git).

```js
// review-core.mjs:112 — выражение заголовка. Группа 2 — НОМЕР, и он был не нужен никому:
const RE_QUESTION_HEADING = /^#{2,4}\s*(Вопрос|Question|Q)\s*(\d+)/iu;
// :189 — ярлык строится из ПОРЯДКОВОГО номера блока:

```

**Наблюдено красным на фикстуре ДО правки:** документ с заголовками `Q1 | Q3 | Q4` дал ярлыки
`Q1 | Q2 | Q3`.

## 🔴 НАХОДКА 2 — НЕ ОПИСАНА В ТИКЕТЕ, НАЙДЕНА ПРИ ЕГО ПОЧИНКЕ, И ОНА ХУЖЕ ПЕРВОЙ

`applyAnswersToDocument` вела **СВОЙ обход заголовков** вместо того, чтобы взять границы у
`questionBlockRanges`, — то есть второй разбор одного факта, ровно против чего написана шапка самого
модуля (*«A duplicated parser is a second truth»*). И этот второй разбор **не нёс защиты `bugs/70`**:
агент, озаглавивший свой разбор цитатой вида `### Q1 = A, и вот что это меняет`, ставит строку,
совпадающую с выражением ДОСЛОВНО. Настоящий разбор такую строку пропускает (номер уже открыл
вопрос), а этот обход считал её вопросом и сдвигал всё последующее сопоставление на единицу.

**Наблюдено красным на фикстуре ДО правки:**

```
    4: ## Q1. Первый вопрос
    6: **Ответ:**                       ← остался пустым
   10: ### Q1 = A, и вот что это меняет  ← ЦИТАТА агента
   12: **Ответ:** B                      ← ответ владельца лёг СЮДА
   17: ## Q2. Второй вопрос
   19: **Ответ:**                       ← его настоящий вопрос остался без ответа
   записано: ["Q2"] · пропущено: []     ← и функция отчиталась УСПЕХОМ
```

Первая находка врёт машинной записи; **вторая портит документ владельца и рапортует об этом
успехом.** Поэтому тяжесть тикета поднята до S1.

## Починка

| находка | лечение | адрес |
|---|---|---|
| 1 | ярлык берётся из ЗАГОЛОВКА (`RE_QUESTION_HEADING`, группа 2); `index` остаётся порядковым и служит только сопоставлению с границами | `parseQuestionBlock` |
| 2 | границы берутся у `questionBlockRanges`, свой обход снят целиком — второго разбора больше нет | `applyAnswersToDocument` |

**Столкновений имён быть не может:** `questionBlockRanges` пропускает второй заголовок с тем же
номером (`bugs/70`), значит номер уникален в пределах документа по построению.

**Доказано:** два блока в батарее контура (**B7** — ярлыки при разорванной нумерации; **B8** —
ответ ложится под свой вопрос при цитатном заголовке), контур **30 → 32 блока, 0 красных**. Две
мутации, каждая красит СВОЙ блок: возврат находки 1 → красный B7; возврат находки 2 → красный B8.
