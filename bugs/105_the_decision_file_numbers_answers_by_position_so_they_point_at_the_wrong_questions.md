# Bug 105 — запись решения нумерует ответы ПО ПОРЯДКУ, и они указывают на чужие вопросы

**Статус:** 🔴 открыт · **Тяжесть:** S2 (документ и сторож, без эпика) · **Найден:** 2026-09-04 19:5x,
сессия 84, при чтении ответа владельца по `interviews/026`
**Класс:** пара «документ ↔ его машинная запись» разошлась — тот же класс, что `bugs/40`,
`interviews/008`, `interviews/013`.

## Симптом

`interviews/026` несёт вопросы с заголовками **Q1**, **Q3**, **Q4** (Q2 был снят с владельца и
заменён разбором на своём месте). Владелец ответил на два. Файл решения
`interviews/decisions/interview_026_*.decision.json` записал их так:

```json
"answers": {
  "Q2": { "choice": "A", "comment": "частота, которая была ЗДОРОВА, но медленно запускалась…" },
  "Q3": { "choice": "A", "comment": "все перемерить. Но в понедельник. не сегодня." }
}
```

**Ключ `Q2` — это ответ на вопрос, который в документе называется `Q3`; ключ `Q3` — на `Q4`.** Ключи
проставлены ПО ПОРЯДКУ следования вопросов (второй и третий по счёту), а не по их собственным
заголовкам.

## Почему это опасно, а не косметика

Это ровно тот дефект, ради которого контур и существует: он записывает решение владельца машинно,
чтобы следующая сессия исполнила его без пересказа. Сессия с пустым контекстом, открывшая файл
решения, исполнит ответ «A» не на тот вопрос — и сделает это уверенно, потому что источник машинный.

**Я сам чуть не прочёл его неверно** и удержался только потому, что пошёл сверять с самим документом
(`grep` по полям «Ответ:»): в документе ответы легли ПРАВИЛЬНО — на строках 127 и 179, под своими
вопросами. То есть врёт не запись в документ, а именно JSON, который читают машины.

Цена ошибки здесь названа владельцем в этой же сессии: один из двух ответов — приказ, роняющий
метрику приёмки с 11 краёв до 4. Исполнить его «не тем вопросом» — испортить документ кривой.

## Улики

## Гипотеза о причине (не проверена чтением кода — это следующий шаг)

Разбор в `tools/lib/review-core.mjs` присваивает вопросу порядковый ярлык `Q<i>` вместо того, чтобы
брать номер из его собственного заголовка. Пока нумерация в документе сплошная (Q1, Q2, Q3…), порядок
и заголовок совпадают, и дефект невидим. Он проявляется ровно тогда, когда нумерация в документе
**разрывается** — а разрывается она законно: снятый вопрос остаётся на месте разбором, и это
предписанное поведение (вопрос, снятый агентом, не удаляется, а объясняется).

## План починки

1. Прочитать разбор заголовков в `review-core.mjs` и подтвердить гипотезу цитатой строки — до правки.
2. Ярлык берётся из ЗАГОЛОВКА вопроса, а не из его порядка.
3. Сторож: фикстура-документ с разорванной нумерацией (Q1, Q3, Q4) — ключи записи обязаны быть
   `Q1`, `Q3`, `Q4`. Красный до починки, зелёный после.
4. Поправить уже записанный `interview_026_*.decision.json` — переименовать ключи под настоящие
   вопросы, с пометкой о поправке внутри файла (оригинал цел в git).

## Решения без владельца

Ярлык — внутренний идентификатор, не развилка владельца. Правится молча, докладывается результатом.
