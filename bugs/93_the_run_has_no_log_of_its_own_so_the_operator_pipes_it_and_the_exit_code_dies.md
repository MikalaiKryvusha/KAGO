**Цена:** `bugs/67` заводился ровно затем, чтобы остановка спасением была видна МАШИНЕ кодом

## ✅ ПОЧИНКА — `--log [смысл]`, ИСПОЛНЕНА 2026-08-31 (сессия 74)

**Ворота намерения:** у прогона нет своего журнала → оператору нужен файл → появляется `| tee` → код
возврата принадлежит `tee`. Спецификация (`bugs/67`) требует, чтобы остановка была видна МАШИНЕ кодом
возврата. Лечится ПРИЧИНА: файл есть — конвейер не нужен.

### 📁 ИМЯ ЖУРНАЛА СТАВИТ МАШИНА — СЛОВО ВЛАДЕЛЬЦА, ПРИШЕДШЕЕ ПО ХОДУ ПОЧИНКИ

Первая редакция принимала `--log <файл>`, и в порядке вечера я написал `runs/sweep/vecher.log`.
Владелец это отклонил дословно: *«не надо называть vecher · есть дата и время на машине — так логи и
называть, в одну директорию складывать, внутри можно делать поддиректории с называнием смысла
прогонов»*.

**Что это поменяло по существу, а не по букве.** Флаг перестал принимать имя файла ВООБЩЕ: он
принимает **СМЫСЛ** прогона, а имя ставит машина.

```
--log peremer-2872   →   runs/logs/peremer-2872/2026-08-31T19-25-41+03-00.log
--log                →   runs/logs/sweep/<дата-время>.log        (смысл взят из режима)
```

Он прав по существу: имя, придуманное под настроение, через неделю не отвечает на вопрос «какой это
был прогон», а штамп отвечает всегда и сам себя сортирует. Побочно исчез целый класс опечаток —
назвать файл нечем, значит и промахнуться именем нельзя, и прежний блок про `--log --dry-run`
превратился в «флаг следом за `--log` именем не станет». Смысл по умолчанию берётся из РЕЖИМА
(`sweep` · `band` · `search` · `dry-run`) — не выдумывается (три двери).

### Что сделано

`startRunLog(argv)` поднимается в ТОЧКЕ ВХОДА, а не внутри `main`: у `main` два десятка точек выхода
(`return 2` на каждом разборе аргументов), и обернуть её тело значило бы двадцать шансов промахнуться
мимо одного. Здесь выход ровно один, и обе его двери — удачная и через исключение — закрывают журнал.

| Решение | Почему именно так |
|---|---|
| **Пишется синхронно** (`writeSync`), а не потоком | поток буферизует, `process.exit` обрывает процесс не дожидаясь слива — потерялись бы последние строки, ровно те, где написана причина остановки. Класс `bugs/37`: улика гибнет тогда же, когда становится нужна |
| **Открывается на дописывание** (`'a'`) | журнал — улика, и два прогона в одну секунду обязаны сложиться, а не затереть друг друга. То же решение владельца, что в `bugs/94`: *«можем накопить случаи, да, это более научный метод»* |
| **Зеркалит, а не подменяет** | вывод уходит И в файл, И в терминал: владелец у машины не должен остаться перед тёмным экраном |
| **Последняя строка — код возврата** | файл, по которому разбирают вечер, обязан САМ отвечать «прогон удался?». Иначе улику опять придётся где-то перехватывать — а тикет ровно про это |
| **Отказ записи прогон НЕ роняет** | диск кончился — причина потерять журнал, а не причина бросить видеокарту в изменённом состоянии. Прибор не старше того, за чем смотрит |

### Решения, принятые без владельца

**Одно, инженерное:** код возврата дописывается В САМ ЖУРНАЛ, а не печатается в терминал. Печать в
stdout изменила бы существующий вывод, а вопрос читателя журнала («удался ли вечер?») и вопрос зрителя
за машиной — разные. Обратимо одной строкой, если владелец захочет видеть код и на экране.
**Именование журналов решением МОИМ не осталось** — владелец его забрал себе по ходу работы, и это
записано выше как отдельный раздел, а не как правка мимоходом.

## Симптом

Я запускал прогон так (и так же поступит любой оператор, которому нужен журнал на диске):

```
npm run engine -- --sweep ... | tee runs/sweep-session73.log
```

Код выхода такого конвейера — это код **`tee`**, а не движка. Оба прогона отчитались `exit code 0`;
второй при этом кончился строкой:

```
ОСТАНОВЛЕНО (fuse-rescue): АПВ НЕУСПЕШНО — аварийная защита не смогла вернуться на пост
```

то есть **ненулевым по существу.** Различитель, ради которого закрывался `bugs/67`, был стёрт
командой запуска.

## Корневая причина — НЕ в конвейере

Конвейер здесь следствие. Причина: **прогон не пишет собственного журнала.** Оператору нужен файл
(разбор, эстафета, форензика), файла нет — значит появляется `tee`, а с ним гибнет код возврата.
Дефект в отсутствующей возможности, а не в привычке оператора.

Это тот же класс, что `bugs/37` и `bugs/78`: улика, которая существует только пока кто-то её
перехватывает, — не улика.

## Почему это опаснее, чем кажется

`bugs/67` закрывался с формулировкой «отказ, невидимый машине». Сегодня он снова невидим машине —
**через другую дверь**. И заметил я это не по коду выхода, а прочитав последнюю строку глазами.
В автономном цикле (`/nightloop`, `/dayloop`) глаз нет: цикл прочитал бы `0` и пошёл дальше,
считая вечер удачным.

## Починка (очевидная, но НЕ начатая — сначала планы)

**`--log <файл>`: движок пишет свой вывод сам,** оператор не ставит конвейер, код возврата доходит
до вызывающего. Второй слой — рельс в `GPU_TUNING_RAILS.md` §2: команда прогона печатается БЕЗ
`tee`, с `--log`.

⚠️ **Не сторож на «отсутствие `tee`»:** сторожу неоткуда узнать, как его запустили. Лечится
устранением ПРИЧИНЫ (файл есть — конвейер не нужен), а не надзором за симптомом.
