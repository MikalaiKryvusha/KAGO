# Bug 106 — два диалекта `ok` в одном проекте, и на стыке рождается блок, который НЕ УМЕЕТ КРАСНЕТЬ

**Статус:** 🟡 ЧАСТИЧНО — обе строки в батарее `fuse` починены 2026-09-05 (сессия 85), перепись
остальных батарей НЕ сделана · **Тяжесть:** S1 (ложный зелёный в батарее аварийной защиты) ·
**Найден:** 2026-09-05, сессия 85, при подготовке приёмки `plans/88` Ш3 — блоки, на которые я
собирался опереться, оказались неспособны покраснеть
**Класс:** ложный зелёный, неотличимый от «не смотрели» ([[EXP-0112]]).

## Симптом

В батарее `fuse` две строки шага Ш5 (`plans/81`) были написаны так:

```js
ok('Ш5 АПВ: защита ПЕРЕЖИЛА срабатывание — вернулась на пост, а не вышла',
  [r.trips >= 1, r.rearms >= 1, r.tripped], [true, true, false]);
ok('Ш5 АПВ: после возврата на пост защита СНОВА СРАБАТЫВАЕТ — взведение настоящее, а не выживание',
  r.trips, 2);
```

А подпись помощника в этом файле — **другая**:

```js
const ok = (name, cond, detail = '') => { if (cond) { pass++; ... } else { fail++; ... } };
```

Второй аргумент — УСЛОВИЕ. Непустой массив истинен всегда; число 2 истинно всегда. Обе строки
горели зелёным **структурно**, чем бы ни кончился прогон. Третий аргумент, задуманный как
«ожидание», молча уезжал в поле подробности, которое печатается только у красных.

## Корень: в проекте ДВА диалекта одного имени

| файл | подпись |
|---|---|
| `fuse.mjs` · `curve-store.mjs` · `death-watch.mjs` · `burn-model.mjs` · `card-generator.mjs` · `polygon-*.mjs` | `ok(name, cond, detail)` |
| **`driver-voice.mjs`** | **`ok(name, got, want)`** |

Строки написаны диалектом `driver-voice` внутри батареи `fuse`. Это ровно та пара
«правда ↔ зеркало», о которой предупреждает реестр пар: два помощника с одним именем и разными
контрактами не расходятся громко — они расходятся молча и в безопасную на вид сторону.

## Чем это оплачено

Обе строки приписаны мутации М4 (`plans/81`, [[EXP-0205]]) — «не сбрасывать `tripOutcomes`».
Проверено 2026-09-05: **М4 не покрасила бы ни одну из них**. Мутация М4, снимающая сброс, оставляет
`r.trips = 1` — непустое число, то есть истина. Значит главный блок шага Ш5 («взведение настоящее, а
не выживание») **пять дней стоял украшением**, а запись «мутация краснит ровно её» была неверна.

Прямых потерь на карте это не дало: сам механизм Ш5 оказался исправен, что показал прогон после
починки. Но опереться на эти строки при приёмке Ш3 значило бы принять работу по несуществующему
доказательству.

## Починка (сессия 85, частичная)

Обе строки переписаны диалектом `fuse`: сравнение стало УСЛОВИЕМ, а измеренное печатается
подробностью (`bugs/102` шаг 2 — «что видел блок, в строке, а не только имя»).

```js
const seenRearm = `трипов ${r.trips} · перевзведений ${r.rearms} · вышел неперевзведённым: ${r.tripped}`;
ok('Ш5 АПВ: защита ПЕРЕЖИЛА срабатывание — вернулась на пост, а не вышла',
  r.trips >= 1 && r.rearms >= 1 && r.tripped === false, seenRearm);
ok('Ш5 АПВ: после возврата на пост защита СНОВА СРАБАТЫВАЕТ — взведение настоящее, а не выживание',
  r.trips === 2, seenRearm);
```

Доказано мутациями того же дня: M1 (снять окно здоровья) и M2 (объявить половину возврата
возвратом) красят в том числе строку «счёт сходится», а M3 и M6 — блоки, написанные взамен зелёных
мутаций.

## Что НЕ сделано и почему это названо, а не замолчано

1. **Перепись остальных батарей не делалась.** Сканирование `fuse.mjs` нашло ровно две строки этой
   формы, и они починены. Остальные батареи проекта (`engine`, `twin`, `curve-store`,
   `stress-tester`, `vf-step`, `polygon-*`, …) **тем же сканом не прогонялись**: у каждой свой
   `ok`, и «третий аргумент — литерал» ловит не все случаи. Это открытая половина тикета.
2. **Сторожа против рецидива нет.** Правильное лечение класса — не перепись, а невозможность:
   один помощник на весь проект, либо линтер, который краснит `ok(...)` с небулевым вторым
   аргументом. Пока не сделано; выбор формы — отдельная работа.
3. **Диалект `driver-voice` не тронут.** Он самосогласован и внутри своей батареи верен. Сводить
   два диалекта в один — правка, которая касается чужих блоков, и она не делается заодно.

## Как проверить, что тикет закрыт

- скан всех батарей на форму «второй аргумент не булев» даёт ноль;
- либо стоит сторож, краснеющий на такой строке;
- и на каждой найденной строке показано мутацией, что после починки она краснеет.
