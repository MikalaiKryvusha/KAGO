# Bug 114 — остановка ОПЕРАТОРОМ записывается как ЗАВИСАНИЕ МАШИНЫ и может навсегда закрыть здоровую частоту

**Статус:** 🟡 AC1·AC2·AC3 ВЗЯТЫ, открыты AC4·AC5 · **Тяжесть:** S2 (карте не вредит; вредит ДОКУМЕНТУ КРИВОЙ — вносит в него
край, которого физически не было, и делает это необратимо) ·
**Найден:** 2026-09-08, сессия 88, разбором журнала после живой полосы `2370→2235` — не чтением
кода, а вопросом «почему приписано зависание на частоте, которую мы сегодня не трогали».

## Вектор цели

**Тип: Avoid.** Не допустить, чтобы решение ЧЕЛОВЕКА остановить прогон превращалось в утверждение о
КРЕМНИИ. Хотим: намерение, оставшееся без вердикта, различает три причины — крах машины, остановку
оператором, смерть процесса по внешней причине — и закрывает частоту краем ТОЛЬКО в первом случае.

## Критерии приёмки

- **AC1.** Прогон, остановленный оператором штатно, закрывает открытое намерение записью с причиной
  «остановлено оператором», а НЕ `ЗАВИС`.
  *Проверка:* остановить прогон на двойнике в середине ступени штатным путём → в журнале у этой
  ступени `verdict` ≠ `ЗАВИС`, и `hangFloors` этой частоты не пополняется.
- **AC2.** Намерение без вердикта, оставшееся после НЕштатной смерти (нет метки остановки),
  по-прежнему закрывается `ЗАВИС` — поведение не ослаблено.
  *Проверка:* убить процесс прогона `process.exit` в середине ступени → следующий запуск закрывает
  её `ЗАВИС`, как сегодня.
- **AC3.** Существующая ложная запись 2197 МГц / 785 мВ от 2026-09-07 13:25:09 помечена поправкой
  в журнале (`writeCorrection`), а не удалена.
  *Проверка:* `npm run journal -- --show 2197` показывает обе записи и поправку к второй.

## Симптом

Живая полоса 08.09 (`--sweep --from 2370 --to 2235`, код возврата 0) в итоговой сводке напечатала:

```
ЗАВИСАНИЙ ПРИПИСАНО: 1 — 2197 МГц / 785 мВ
ЗАБЛОКИРОВАНО ДВУМЯ ЗАВИСАНИЯМИ ПОДРЯД: 2197 МГц / 785 мВ
```

**2197 МГц лежит НИЖЕ полосы (2370…2235) — сегодня эта частота не трогалась вовсе.**

## Улики — две записи «ЗАВИС» разной природы

`runs/sweep/journal.jsonl`, строки 1788 и 1794.

**Первая (`seq 886`, 2026-09-07T13:24:19) — НАСТОЯЩЕЕ зависание, поля заполнены:**

```json
{"outcome":"hung","verdict":"ЗАВИС","decidedBy":"аварийная защита","deliveredMhz":2190,
 "redBlocks":[{"name":"форма furnace/sustained@0: CRASH","detail":"процесс не дожил 1 раз(а)"}],
 "why":"СРАБОТАЛА АВАРИЙНАЯ ЗАЩИТА (САЗ) на 2197 МГц / 785 мВ … МАШИНА ЖИВА …"}
```

**Вторая (`seq 889`, запись без времени) — ПУСТАЯ, восстановлена при следующем запуске:**

```json
{"at":null,"appliedDeltaMhz":null,"decidedBy":null,"deliveredMhz":null,"outcome":"hung",
 "verdict":"ЗАВИС","writeSettled":null,
 "why":"НАМЕРЕНИЕ БЕЗ ВЕРДИКТА: ступень 2197 МГц / 785 мВ была в полёте, когда прогон перестал
        существовать. Значит эта ступень и повесила машину — вердикт ЗАВИС, первого класса
        наравне с SDC и CRASH (слово владельца 2026-08-15)"}
```

**А `STATUS.md` про тот прогон говорит:** *«`--sweep 2370→2167`, **оборван по слову владельца** на
2197 МГц»*. То есть прогон не умер — его остановил человек.

## Причина

Правило «намерение без вердикта = `ЗАВИС`» (`plans/15` §4.4) написано под ОДИН сценарий и он
верен: зависание, требующее кнопки сброса, уносит страничный кэш ОС, и журнал, durable только при
штатном завершении, durable ровно никогда, когда это важно. Поэтому открытое намерение — это ответ.

**Но сценариев ТРИ, а различается один:**

| что случилось | открытое намерение | правильный вердикт | что пишется сейчас |
|---|---|---|---|
| машина зависла | остаётся | `ЗАВИС` ✅ | `ЗАВИС` |
| **оператор остановил прогон** | остаётся | **«остановлено оператором»** | 🔴 `ЗАВИС` |
| процесс убит извне (перезагрузка, задача-сторож) | остаётся | «прервано, причина неизвестна» | 🔴 `ЗАВИС` |

## Цена

- **Сегодня мала:** 785 мВ на 2197 МГц и правда плохое — это доказала ПЕРВАЯ запись, настоящая.
  Пол зависания на этой частоте обоснован, ложна только его ВТОРАЯ половина.
- **В следующий раз может быть высокой:** остановка по слову владельца посреди ЗДОРОВОЙ ступени
  запишет ей край, которого не было. `hangFloors` необратим для спуска («спуск туда больше не
  идёт»), значит частота уходит из работы навсегда, а документ кривой начинает врать о кремнии.
- И отдельно: **«два зависания подряд» — единственная аварийная остановка, оставленная владельцем**
  (`plans/15` §4.4). Фабриковать её половину из решения человека — значит расшатывать тормоз,
  который он себе оставил.

## План починки

1. **Ш1 — метка штатной остановки.** При остановке по слову оператора (и при обработанном сигнале)
   прогон дописывает в журнал запись `state:"aborted"` с причиной ДО выхода. Это дешевле, чем
   угадывать потом.
2. **Ш2 — читатель различает три случая.** `resumeState` (или его чистый сосед) закрывает открытое
   намерение `ЗАВИС` только если метки штатной остановки НЕТ. Есть метка — вердикт «остановлено
   оператором», в `hangFloors` не попадает.
   ⚠️ **`resumeState` ПИШЕТ в журнал — звать её на живом прогоне нельзя** (правило проекта);
   различение делать там же, где сегодня рождается пустая запись.
3. **Ш3 — поправка существующей записи.** `writeCorrection` на `seq 889` (не удаление — правило
   `bugs/85`/`plans/86`: журнал исправляют поправкой, а не переписыванием).
4. **Ш4 — блоки.** Положительная ветка (метки нет → `ЗАВИС`, поведение не ослаблено), отрицательная
   (метка есть → не `ЗАВИС`, пол не пополняется), и мутация, снимающая различение, обязана покрасить
   свой блок.

## Решения, принятые без владельца

- **Завести тикет, а не спросить.** По его правилу 07.09 (`interviews/028`) проверка «изменится ли
  от ответа то, что он увидит?» даёт «нет»: он увидит, что остановка больше не портит документ.
- **Не трогать поведение при НЕштатной смерти.** Ослаблять его нельзя — оно оплачено `bugs/76`.
