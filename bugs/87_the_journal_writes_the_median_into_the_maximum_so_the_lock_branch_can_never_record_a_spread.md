тега `DONE` тикет не получает (`TESTING_FRAMEWORK.md`, ворота 6a).
Найден 2026-08-31 (сессия 71) при исполнении шага 1 эстафеты по `bugs/86`.

**Цена:** не вердикт, а СЛЕПОТА АРХИВА. Ни одно решение по этому полю не принимается (`worstSpreadMhz`

## Вектор цели

**Боль:** владелец заказал замер «как связаны размер подъёма кривой и разброс выданной частоты внутри
прожига» (`bugs/86`, эстафета сессии 70, шаг 1). Журнал развёртки на этот вопрос ответить не может:
у каждой ступени, где частоту держало ЗАКРЕПЛЕНИЕ, разброс записан нулём — в том числе у сорвавшейся,
где прибор в ту же секунду напечатал размах 158 МГц.
**Куда хотим:** запись прожига несёт ту же величину, по которой судит сторож, — то есть настоящие
минимум и максимум под нагрузкой, на ОБЕИХ ветках держателя. Тип цели — **Achieve**.

### Критерии приёмки

1. **AC1.** Для ступени, где сторож закрепления напечатал размах, запись журнала ДОЛЖНА нести
   `deliveredMaxMhz`, равный максимуму нагруженных проб, а не медиане.
   *Scale:* МГц · *Meter:* сверка записи журнала с пробами того же прожига (`npm run hold`) ·
   *Target:* расхождение 0 МГц на всех ступенях с держателем «закрепление частоты».
2. **AC2.** Разброс, вычисляемый по журналу, ДОЛЖЕН совпадать с разбросом, по которому судит
   `verifyLockUnderLoad`. Сегодня журнал считает `max − медиана`, сторож — `max − min`; это две
   разные величины под одним именем.
   *Scale:* МГц · *Meter:* тот же прогон · *Target:* 0 расхождения.
3. **AC3.** Стенд ДОЛЖЕН быть способен породить прожиг, у которого максимум отличается от медианы —
   иначе репетиция этого класса невозможна по построению.
   *Meter:* мутация, кладущая медиану в максимум на живом пути, обязана покраснеть хотя бы один блок.
   *Target:* мутация красная (сегодня — зелёная).

## Форензика

**Два места записи, и первое кладёт не то число** (`vf-step.mjs`):

```js

  out.deliveredMhz = proof.delivered;
  out.deliveredMaxMhz = proof.delivered;     // 🔴 proof.delivered — это МЕДИАНА
}

// ветка ПОТОЛКА, :1332-1338 — здесь всё верно
const median = sorted[Math.floor(sorted.length / 2)];
const max = Math.max(...clocks);
out.deliveredMhz = median;
out.deliveredMaxMhz = max;
```

`proof` приходит из `ladder-descent.verifyLockUnderLoad`, и та возвращает `delivered: c.median`
(`ladder-descent.mjs:216, 224`) — при том, что `c.min` и `c.max` у неё В РУКАХ: она их печатает
в тексте отказа и на них же судит.

**Опись по архиву — предсказание кода сошлось с данными.** Все ступени журнала, у которых есть оба
числа выдачи (91 из 823; раньше 25.08 поля не существовало — это `bugs/54`), в разрезе держателя:

| держатель | ступеней | разброс = 0 | разброс > 0 |
|---|---|---|---|
| кривая | 27 | 17 | 10 |
| кривая + замок | 57 | 53 | 4 |
| **закрепление частоты** | **7** | **7** | **0** |

Семь из семи. Ни одной ступени с закреплением за всю историю журнала разброс показать не смогла —
включая ту, у которой он был 158 МГц.

**Второй дефект того же места: минимума в журнале нет вовсе.** `deliveredMinMhz` не существует нигде
в проекте (проверено обходом). Поэтому величина, которую журнал зовёт разбросом
(`sweep-journal.mjs:806`, `deliveredMaxMhz − deliveredMhz`, то есть **max − медиана**), это НЕ та
величина, по которой судит сторож (**max − min**). У сорвавшейся ступени первая равна 11,5 МГц,
вторая 158. Одно имя, два разных числа.

## 🔬 ПОЧЕМУ КЛАСС НЕ ЛОВИЛ НИКТО — ТРИ ДЫРЫ В ФИКСТУРЕ, А НЕ В СТОРОЖАХ

Путь записи целиком проверяется офлайн с эпика 59 (`vfstep --selftest`, фейковое устройство). Он
дефект не поймал, и вскрытие дало **три независимых причины, каждая из которых по отдельности
достаточна**, — все три в ФЕЙКЕ, ни одной в судьях:

1. **Фейковый сэмплер писал двенадцать ОДИНАКОВЫХ проб** (`clocks.gr: CAP - 7` ×12). У такой серии
   минимум = медиана = максимум, и вопрос «что лежит в поле максимума» на ней не стоит.
2. **Фейк писал строку НЕ ТОЙ ФОРМЫ, что настоящий сэмплер** — плоский объект вместо `{i, sample}`.
   Ветка потолка плоский терпит (`r.sample ?? r`), а ветка ЗАКРЕПЛЕНИЯ идёт через
   `summarizeSamples`, который требует `r.i >= 0 && r.sample` и на плоском видит НОЛЬ проб.
3. **Фейк не реализовывал контракт формы `uniform`** — `writeCurve` принимал только массив, а
   `uniform` передаёт СКАЛЯР (`vf-step.mjs:953`). Любой офлайн-прогон закреплённой ступени падал
   на `offsets.map is not a function`.

**Совокупный итог: закреплённая ветка НИ РАЗУ не проходила офлайн за всю жизнь порта.** Судьи были
исправны; данные, на которых вопрос вообще стоит, до них не доходили ([[EXP-0205]]).

молчание старой записи» заведён ОТДЕЛЬНЫЙ блок.

## Причина

Поле добавили на ветку закрепления позже, чем на ветку потолка, и добавили из того, что было под
рукой — из `proof.delivered`. Собственный комментарий этого места объясняет, ЗАЧЕМ поле здесь
(«путь, который меряет частоту и потом её роняет, оставляет развёртку без ключа для строки»), и
про максимум не говорит ничего: половину задачи закрыли, вторую не заметили. Бритва Хэнлона —
недосмотр, а не срез угла.

**Класс тот же, за который проект уже платил трижды:** `bugs/54` (журнал молча ронял выданную
частоту), `bugs/84` (накопитель читал поле, которого развёртка не выставляет), [[EXP-0205]]
(«мутировать надо ПРОВОДКУ, а не судью»). Здесь проводка не отсутствует — она **подменяет число**,
что хуже: пустое поле заставляет посмотреть, а заполненное неверным числом заставляет поверить
([[EXP-0206]]).

## План починки

1. **`verifyLockUnderLoad` возвращает то, что уже посчитала.** Добавить в её ответ `min` и `max`
   рядом с `delivered` — она их вычисляет строкой выше и выбрасывает. Ни одного нового вычисления.
2. **`vf-step.mjs` ветка закрепления пишет `deliveredMaxMhz` из `proof.max`**, а не из
   `proof.delivered`.
3. **Завести `deliveredMinMhz`** и писать его на ОБЕИХ ветках; журнал считает разброс как
   `max − min` — ту же величину, по которой судит сторож (закрывает AC2). Старое поле не трогать:
   `deliveredMhz` остаётся медианой и остаётся ключом строки.
4. **`trap-suite.mjs` учится разводить медиану и максимум** — иначе AC3 недостижим и класс снова
   некому будет ловить.
5. **Мутация как доказательство:** вернуть `deliveredMaxMhz = медиана` на живом пути и убедиться,
   что блок краснеет.

## Отдельно названный риск, найденный рядом и НЕ являющийся этим багом

`verifyLockUnderLoad` считает размах по ВСЕМ нагруженным пробам, без отсечки разгона. Первая
нагруженная проба часто ловит карту на подъёме: замерено по архиву — **у 184 прожигов из 391**
первая нагруженная проба лежит ниже медианы больше чем на допуск. На ветке потолка это безвредно
(там размах не судит), а на ветке закрепления сторож способен объявить здоровую ступень «не
фиксацией». **Наблюдения такого пока НЕТ** — из десяти прожигов с закреплением разгон попал в окно
ровно у одного, и это сорвавшийся, который и без разгона был сорван. Риск назван, в дефект не
раздут; если он выстрелит — это отдельный тикет.
