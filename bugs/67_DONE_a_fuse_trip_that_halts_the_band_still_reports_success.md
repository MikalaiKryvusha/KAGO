**Класс:** отказ, невидимый машине — родня `bugs/48` (намеренная остановка записана зависанием) и

## Симптом

Судья-предохранитель трипнул, полоса штатно встала до следующей ступени с именованной причиной —
**и процесс развёртки вышел с кодом 0**.

```
$ node automation-engine/engine.mjs --sweep --card virtual --from 2842 --to 2812 \
      --max-depth 300 --twin-arm --twin-arm-n 1
...
  ПОЛОСА ОСТАНОВЛЕНА ВНЕШНИМ СТОПОМ ПЕРЕД 2835 МГц: судья вышел (код 2 — СПАСЕНИЕ сработало)
КОД ВОЗВРАТА: 0
```

`--twin-arm-n 1` здесь — не хитрость, а способ сделать трип ДЕТЕРМИНИРОВАННЫМ: порог 1 мс ниже
любого зазора канала, поэтому судья трипает на первом же такте. Тот же исход пойман ТРИЖДЫ
случайно — сеткой `plans/65` на здоровых прогонах при N = 10 и 15 мс
(`benches/runs/tune-n-2026-08-29T10-49-01-03-00.jsonl`, строки с исходом `ложно`, у всех
`exitCode: 0`).

## Почему это дефект, а не оформление

Полоса встаёт ПОТОМУ, что предохранитель решил: машина умирает. Человек в терминале это видит —
строка напечатана. **Вызывающий не видит ничего:** ночной прогон, скрипт, сетка, планировщик
получают ровно тот же ноль, что и от чистого завершения. Эпик 51 существует ради прогонов, где
человека за машиной НЕТ (`plans/51` → граница автономии), а значит «доложить срабатывание»
обязано жить в коде возврата, а не только в тексте.

Механика: в ветке внешнего стопа отчёт объявляется успешным, если хоть одна частота закрыта
(`report.ok = report.closed > 0`). Для стопов «оператор попросил» это верно; для трипа
предохранителя — нет: спасённая ступень по канону эпика ОТКАЗ, а спасённый прогон — происшествие.

## ✅ ПОЧИНКА (2026-08-29 22:1x) — обе половины, проверено живой пробой

**Живая проба, та же команда из раздела Repro:**

```
КОД ВОЗВРАТА: 1                       ← было 0
  ПОЛОСА ОСТАНОВЛЕНА ВНЕШНИМ СТОПОМ ПЕРЕД 2835 МГц: судья вышел (код 2 — СПАСЕНИЕ сработало):
  читай журнал судьи в песочнице …\benches\runs\twin-2026-08-29T22-03-06-03-00
ОСТАНОВЛЕНО (fuse-rescue): ПОЛОСА ОСТАНОВЛЕНА ВНЕШНИМ СТОПОМ ПЕРЕД 2835 МГц: …
```

**(1) Различитель — ПОЛЕ, а не слова.** `stopWhen()` возвращал строку-причину; теперь возвращает
`{ why, rescue }`. Разбирать причину регуляркой по тексту было бы парой «правда↔зеркало» ровно там,
где её легче всего завести: текст правят ради читателя, и классификация тихо разъезжается с ним.
Признак ставит тот, кто ЗНАЕТ причину: код 2 судьи — спасение; любой другой код — судья умер сам
(полоса тоже встаёт, но это отказ ПРИБОРА, а не срабатывание спасения).

**(2) Код возврата.** `report.ok = rescue ? false : report.closed > 0` · `report.stoppedBy =
'fuse-rescue'`. Заодно включается уже существующая строка сводки `ОСТАНОВЛЕНО (<кто>): <почему>` —
то есть причина попадает в вывод не только в момент стопа, но и в итог.
⚠️ **Что при этом НЕ изменилось и проверено:** закрытые до трипа частоты остаются закрытыми
(`closed` = 3, отдельный блок) — добытое знание не теряется, меняется вердикт ПРОГОНА. Это две
разные вещи, которые прежняя строка схлопывала в одну.

**(3) Путь журнала — одно значение на двух читателей** (`fuseJournalHintFor`): строка подъёма
предохранителя и причина стопа берут его из одной функции. Пара схлопнута, а не поставлена под
сторожа (R14a). Функция вынесена НЕ ради красоты, а ради блока: пока путь был константой внутри
текста, доказать его было нечем — и он пять дней посылал читателя мимо улики.

**(4) Блоки — 375 → 380, мутации ×4, каждая краснит РОВНО свой блок:**

| мутация | что покраснело |
|---|---|
| откат починки (`ok = closed > 0`) | «СПАСЕНИЕ — происшествие»: получено `true`, ждали `false` |
| любой стоп объявлен провалом (`ok = false`) | «стоп ОПЕРАТОРА»: получено `false`, ждали `true` |
| имя стопа одно на обе причины | «стоп ОПЕРАТОРА»: получено `fuse-rescue`, ждали `external-stop` |
| подсказка журнала снова константа | «двойник ведёт в ПЕСОЧНИЦУ»: получено `[false, true]` |

**Названный тикетом риск снят прогоном, а не рассуждением:** взведённый здоровый смоук
(`--smoke --armed`, P63-AC5) — код 0, трипов ноль, I1 держится; репетиция удушения
(`--rehearse-death strangle`) — 8 проверок из 8, код 0. Оба судят по журналу судьи и тексту, а не по
коду развёртки, поэтому починка их не задела.

молчит на починенном. Это не фикстура: улики — вывод двух настоящих прогонов.

## Решения, принятые без владельца

- **Имя нового класса стопа — `fuse-rescue`.** Внутренний инженерный идентификатор, витрины не
  касается (правило бренд-имени `GOAL.md` под него не подпадает). Обратимо переименованием.
- **Форма различителя — поле в возвращаемом объекте, а не второй callback.** Меньше движущихся
  частей: `stopWhen` уже вызывался в одном месте, и двух дорог стопа заводить незачем.

## Прежний план починки (исполнен целиком)

1. Различить причины внешнего стопа: **трип предохранителя — не то же, что просьба оператора.**
   Отчёт уже несёт `stoppedBy`/`why`; нужен признак, по которому вызывающий отличает спасение
   (сегодня оба схлопнуты в `external-stop`).
2. Код возврата развёртки: спасение → ненулевой, с ИМЕНЕМ причины в последней строке вывода.
   ⚠️ Не ломая существующих вызывающих: `--smoke` эпика 59 и сетка `plans/65` читают код 0 как
   «прошло», и у них появится новый смысл — их проверки правятся тем же шагом.
3. Текст причины стопа выбирает путь журнала по тому, ГДЕ судья пишет (двойник ↔ живой), а не по
   константе — пару «правда↔зеркало» лучше схлопнуть, чем сторожить (R14a).
4. Блоки: полоса встала трипом → код ненулевой и причина названа; полоса встала просьбой
   оператора → прежний код. Мутация на каждый.
