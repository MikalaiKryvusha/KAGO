# Баг 95 — восемь приборов запускают свой CLI ПРИ ИМПОРТЕ и убивают импортирующий процесс

**Статус:** 🟡 **ОДИН ПОЧИНЕН, СЕМЬ В ОПИСИ** · **Заведён:** 2026-08-31 (сессия 73)
**Найден:** попыткой набора `vfstep` импортировать разбор имени у `hold-vs-raise.mjs`, чтобы НЕ
заводить второй такой же разбор. Вместо блока набор напечатал отчёт чужого прибора и вышел.
**Цена, и она коварная:** дефект наказывает ровно за то поведение, которого канон требует — за
переиспользование вместо копии.

---

## Симптом

```js
const { parseBurnName } = await import('../../tools/hold-vs-raise.mjs');
```

Импорт исполнил CLI прибора: он увидел `--selftest` в `process.argv` вызывающего, прогнал СВОЙ
набор и вызвал `process.exit`. Набор `vfstep` умер, не напечатав ни одного своего блока.

## Корневая причина

На верхнем уровне модуля стояло голое:

```js
const argv = process.argv.slice(2);
process.exit(argv.includes('--selftest') ? selftest() : report());
```

Модуль ES исполняется при импорте целиком. Значит любой импорт = чужой прогон + `process.exit`.
И `process.argv` принадлежит ВЫЗЫВАЮЩЕМУ — прибор читает чужие флаги как свои.

## Почему это опаснее обычной неаккуратности

**Дефект наказывает за правильное поведение.** Канон требует не плодить вторую копию разбора
(`PHILOSOPHY.md` → DRY; пара «правда ↔ зеркало» расходится молча). Сессия, попробовавшая
переиспользовать и получившая непонятный обвал, сделает ЕСТЕСТВЕННЫЙ вывод — «импортировать
нельзя» — и напишет копию. То есть дефект производит именно те пары, от которых проект защищается.

## 🔴 Я НАСТУПИЛ НА ЭТОТ ЖЕ ДЕФЕКТ, ПОКА ЕГО ОПИСЫВАЛ — и это лучшая иллюстрация его цены

Опись выше снята **циклом импорта по `tools/*.mjs`**. Импорт — по определению этого дефекта —
ИСПОЛНИЛ приборы. Последствия, найденные не мной, а `git status` при коммите:

| что изменилось само | чем это было |
|---|---|
| `assets/curve-map.html`, `assets/dashboard/sweep.html` | перегенерированы страницы |
| `workloads/MANIFEST.json` | новый `built_at` и три новые `binary_sha256` |
| `workloads/furnace.exe` · `branchy.exe` · `sdc_fma.exe` | 🔴 **ПЕРЕСОБРАНЫ БИНАРНИКИ ПРОЖИГА** |

**Пересобраны те самые нагрузки, которыми меряется карта владельца.** Диагностика, задуманная как
чтение, оказалась записью — и записью в артефакты, от которых зависит каждый вердикт стабильности.

**Проверено прибором проекта, а не рассуждением** (`npm run stress -- --verify-baseline`):
**эталонов 6, сошлись 6**, штампы драйвера и VBIOS на месте. То есть пересборка из тех же
исходников тем же инструментом дала то же поведение, изменились только метки сборки. **Вреда нет,
и это ИЗМЕРЕНО, а не предположено.**

**Урок, который дороже самого дефекта:** «безопасная диагностика» — это утверждение, требующее
проверки, а не свойство слова «прочитать». Импорт модуля в языке, где модуль исполняется, — это
ЗАПУСК. Признак, дешёвый и работающий: **`git status` ДО и ПОСЛЕ любой диагностики, которая
трогает чужой код.** Здесь он и сработал — иначе три пересобранных бинарника уехали бы в коммит
незамеченными, а следующая сессия искала бы, почему у прожига поменялась контрольная сумма.

## Починка

Образец уже есть в проекте и изобретать не пришлось (`PHILOSOPHY.md` → лучшие практики):
`fuse.mjs:1837` — `isMainThread && process.argv[1] && resolve(argv[1]) === resolve(здесь)`.

Для `tools/` хватает половины (воркеров у них нет):

```js
const isEntry = process.argv[1] && resolve(process.argv[1]) === resolve(fileURLToPath(import.meta.url));
if (isEntry) { /* CLI */ }
```
