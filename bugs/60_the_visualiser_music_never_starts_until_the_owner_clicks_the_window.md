# Bug 60 — музыка визуализатора молчит, пока владелец не кликнет по окну, и страница об этом не говорит

**Статус:** 🔧 ПОЧИНЕН 2026-08-26 20:3x, ЖИВОГО ПОДТВЕРЖДЕНИЯ ЖДЁТ — наблюдение доступно только глазу владельца.
**Версия:** `main` @ `b5317f6` · **Где:** `assets/dashboard/_sound.js` → `trackStart()`
**Когда/контекст:** найден ВЛАДЕЛЬЦЕМ 2026-08-26 во время живого прогона развёртки.

---

## Слово владельца, дословно

> *«в визуализатере музыка Глубокий космос почему-то не запускается. пока браузер в фоне, пока я по
> нему не кликну, чтобы вывести в фореграунд — странное поведение»*

## Симптом

Окно наблюдения поднимается САМИМ ПРОГОНОМ (`ОКНО НАБЛЮДЕНИЯ: не открыто — поднимаю сам, ОТДЕЛЬНЫМ
ПРОЦЕССОМ`). Страница приходит в браузер **без единого жеста человека**. Тема «Глубокий космос»
выбрана умолчанием (`TRACK_INDEX = 3`), страница показывает, что звук включён, — и **тишина**.
Музыка начинается ровно тогда, когда владелец кликает по окну, чтобы вывести его на передний план.

## Причина — политика автозапуска, и она НЕ дефект браузера

Браузер не даёт звучать до жеста человека. Это его право и обойти это нельзя ничем — ни одной
строкой кода. **Дефектом было МОЛЧАНИЕ о том, что мы упёрлись в эту политику.**

Прежняя редакция ловила отказ и не делала ничего:

```js
const p = trackEl.play();
if (p && p.catch) p.catch(() => { /* автозапуск не дали — щелчок человека вернёт сюда же */ });
```

Комментарий верен на стенде прослушивания, где человек сам открыл страницу. В бою страницу
открывает ПРОГОН, и жеста не было вовсе.

⚠️ **Класс был предвиден этим же файлом и не закрыт.** Геттер `running` в том же модуле несёт
дословно: *«окно поднято автозапуском, страница честно позвала `toggle(true)`, а браузер оставил
контекст усыплённым, потому что человек ещё ничего не щёлкнул. Без раздельных фактов кнопка сказала
бы „ЗВУК ВКЛ“ в полной тишине»*. Ровно это и произошло — различение завели, а на пути записанной
темы им не воспользовались.

Родня: `bugs/27` — окно наблюдения считалось живым, пока не спросили сам транспорт. Тот же класс:
НАМЕРЕНИЕ страницы принято за СОСТОЯНИЕ железа.

## Лечение

Две вещи, обе честные — обойти политику нельзя, поэтому обходить и не пытаемся:

1. **Сказать вслух.** При отказе автозапуска строка состояния показывает
   `ЖДЁТ ЩЕЛЧКА ПО СТРАНИЦЕ — браузер не даёт звук без него` вместо молчаливого «играет».
2. **Вернуться на первом же жесте.** Одноразовые слушатели на `pointerdown`, `keydown`,
   `visibilitychange` и `focus`. Последние два и есть сценарий владельца: окно поднято в фоне, он
   кликает по нему, вкладка становится видимой. Перед перезапуском будится `AudioContext` — иначе
   граф отдаст тишину. Слушатели снимаются первым же срабатыванием: подписка, живущая после того,
   как сделала своё дело, — это утечка, а не надёжность.

Страница пересобрана: `node tools/build-dashboard-page.mjs`, сторож сборки в `npm run check` зелёный.

## Чего лечение НЕ делает

Не пытается обмануть политику автозапуска, не создаёт `AudioContext` до жеста, не проигрывает звук
беззвучно ради «разблокировки». Всё это — приёмы против правил браузера, и они ломаются на
следующем его обновлении.

## Проверка — только глазом владельца

🔴 **У агента нет сенсора на браузер владельца.** Проверяется так: перезагрузить окно наблюдения,
не кликая по нему, — строка обязана сказать «ЖДЁТ ЩЕЛЧКА»; кликнуть — музыка обязана пойти.
Пока владелец этого не подтвердил, статус остаётся 🔧, а не ✅.

## Решения, принятые без владельца

- **Текст строки состояния** выбран агентом. Регистр инструмента, без разговорных слов.
- **Четыре входа вместо одного** (`pointerdown`, `keydown`, `visibilitychange`, `focus`): «жест» у
  браузеров понимается по-разному, и сценарий владельца — именно возврат вкладки вперёд.
- **Не тронуты остальные темы**: у них нет записанного файла, они синтезируются графом и отказа
  `play()` не дают. Расширять правку туда без нужды — лишняя сущность.
