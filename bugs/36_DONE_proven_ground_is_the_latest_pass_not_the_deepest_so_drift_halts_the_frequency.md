# Bug 36 — доказанной землёй считается ПОСЛЕДНЯЯ прошедшая ступень, а не САМАЯ ГЛУБОКАЯ, и дрейф таблицы останавливает частоту

**Status:** ✅ DONE
**Version/build:** `HEAD` = `41ff784` · **When/context:** 2026-08-23 11:3x +03:00, **второй живой
прогон подряд при владельце.** Полоса 2820…2700 встала на 2820 МГц через 295 с, покрытие 0 из 17.

## Symptom

```
2820 МГц ← 875 мВ (глубина −160 мВ)
таблица уехала: 875 мВ обслуживало 2287 МГц, теперь 2280 МГц
ШАГ ОТ ДОКАЗАННОГО СЛИШКОМ ГЛУБОК: на 2820 МГц доказано 915 мВ, заказано 875 мВ,
а после записи частоту обслуживало 875 мВ — это 40 мВ от доказанного при разрешённых 35
ОСТАНОВЛЕНО (halt) · ПОКРЫТИЕ: закрыто 0 из 17 (0 %)
```

**865 мВ прошли на этой же частоте В ЭТОМ ЖЕ ПРОГОНЕ, четырьмя минутами раньше** (первая же ступень,
затравка из журнала). То есть 875 мВ — не тёмная территория, а область, уже доказанная сегодня.
Сторож `bugs/03` защищает от прыжка в НЕИЗВЕСТНОЕ; здесь известно.

## Root cause — код не делает того, что утверждает его собственный комментарий

`engine.sweepFrequency`, строка передачи земли в ступень:

```js
// `lastPass` is the deepest voltage this frequency has actually SURVIVED
provenMv: lastPass ?? startMv,
```

А присваивается оно так:

```js
if (r?.outcome === 'passed') { lastPass = provedMv; continue; }
```

**Это ПОСЛЕДНЯЯ прошедшая, а не самая глубокая.** Пока карта холодная, они совпадают, и разницы не
существует. Прогретая карта их разводит: ось частот сползает с нагревом (≈1,7 МГц на градус, R14b),
и заказ 860 мВ обслуживается уже 915 мВ. Замер честен — прожиг шёл при 915, — но `lastPass`
поднимается на 915 и **забывает, что 865 уже прошли**. Дальше каждая ступень меряется от завышенной
опоры, и первая же настоящая попадание-в-цель (875 → 875) объявляется прыжком в 40 мВ.

Ход прогона, числами из лога:

| заказано | обслуживало | что стало с землёй |
|---|---|---|
| 865 | 865 ✅ PASS | земля 865 — **глубочайшая за прогон** |
| 860 | **915** ✅ PASS | земля поднялась на 915 |
| 910 · 900 | 915 ✅ | земля 915 |
| 895 · 890 · 885 | 895 ✅ | земля 895 |
| **875** | **875** ✅ | **отвергнуто: 915 − 875 = 40 > 35** |

**Механизм последней строки — сверен по журналу, а не выведен рассуждением** (`readJournal`, чистое
чтение; `resumeState` здесь звать нельзя, она пишет):

| seq | заказ | обслужило | исход |
|---|---|---|---|
| 648 | 865 | **865** | PASS ← глубочайшая доказанная |
| 653 · 654 · 655 | 860 · 910 · 900 | **915** | PASS ← земля уехала на 915 |
| 656 · 657 · 658 | 895 · 890 · 885 | 895 | PASS ← это уже УТОЧНЕНИЕ |
| 659 | 875 | 875 | **void**, хотя вердикт оракула PASS |

Лестница спуска кончилась на полу зависания (850 мВ), и началось уточнение края. `refineEdge` ведёт
СВОЙ счёт вглубь (`pass`), а земля, которую он передаёт каждой ступени, берётся из ВНЕШНЕЙ `lastPass`
и остаётся замороженной на 915. Отсюда и «доказано 915» в отказе: это не ошибка цитаты — это
действительно то число, которым судили.

**Вторая половина дефекта, следствие первой:** вилка края получилась 850…915 вместо 850…865, то есть
уточнение перебирало ступени, заведомо лежащие выше уже доказанного.

## Почему «самая глубокая» — безопасно, а не послабление

Стена `bugs/03` бьёт по РАЗМЕРУ ШАГА в неизвестное. Самая глубокая прошедшая ступень — это ровно
граница известного: ниже неё темно, выше неё доказано. Анкер на завышенной опоре делает стену
формально уже, но ценой ложных остановок на территории, за которую уже заплачено прожигами.
Формулировка `interviews/009` и рельса S2 — «глубина от ДОКАЗАННОГО» — описывает именно это.

## Fix plan

1. Земля = САМОЕ ГЛУБОКОЕ прошедшее напряжение этой частоты В ЭТОМ ПРОГОНЕ. Одна строка:
   `lastPass = Math.min(lastPass ?? Infinity, provedMv)`.
2. Уточнение получает ту же глубочайшую землю — тогда вилка сужается сама (850…865 вместо 850…915).
3. Блоки: промах вверх не поднимает землю · шаг от глубочайшей в пределах стены проходит ·
   настоящий глубокий прыжок по-прежнему `void`. Мутации на каждую половину.
