# Bug 35 — сторож противоречия принимает стену рычага за утверждение и блокирует ЛЮБУЮ запись в документ

**Status:** ✅ DONE
**Version/build:** `HEAD` = `049abbc` · **When/context:** 2026-08-23 11:0x +03:00, **на живом прогоне
при владельце.** Развёртка 2820…2700 нашла край 2820 МГц за 184 с и встала при сохранении.

## Symptom

```
ОСТАНОВЛЕНО (document): ДОКУМЕНТ ПОСЛЕ ЗАПИСИ 2820 МГц НЕ ПРОШЁЛ СВОЙ ЖЕ СТОРОЖ (1):
frequencies[29].voltageMv — 2872 МГц требует 1000 мВ, а более ВЫСОКАЯ 2880 МГц — только 875 мВ.
ПОКРЫТИЕ: закрыто 0 из 17 (0 %)
```

Работа прогона потеряна целиком: край найден, четыре прожига пройдены, а на диск не поехало ничего.
**И следующий прогон встанет там же** — противоречие лежит в документе и никуда не денется.

## Root cause

Строка 2872 МГц несёт теги `stop:lever-limited, origin:ratcheted`:

| тег | что означает |
|---|---|
| `stop:lever-limited` | спуск остановил НАШ рычаг ±1000 МГц. **Отказа никто не видел** |
| `origin:ratcheted` | число поставил ХРАПОВИК по требованию другой строки. **Оно не её** |

Ни одно из двух не является утверждением о кремнии. Разбор этого уже написан в проекте — в
собственной шапке `curve-store.demandsVoltage`, заведённой 2026-08-22 ровно на этот класс:

> *«Строка „предел рычага“ говорит „ниже мы не смогли попросить“, а не „ниже карта не может“»* ·
> *«поднятая храповиком строка не требует ничего — она СЛЕДСТВИЕ, а не причина»*

**Храповик этот предикат спрашивает, а сторож противоречия — нет.** `firstInversion` фильтрует
только по `isUnmeasured`, поэтому строка-стена и строка-эхо участвуют в сравнении как полноценные
замеры и могут «противоречить» настоящему.

## Масштаб класса (инвентаризация, а не оценка)

В `curves/measured.json`: **29 строк `origin:ratcheted`**, из них **28 — `stop:lever-limited`**, то
есть ни одна не измерила своё значение сама. Любая из них способна заблокировать запись.

## Fix plan

1. `firstInversion` сравнивает только строки, которые ТРЕБУЮТ своё напряжение (`demandsVoltage`) —
   тот же предикат, которым уже пользуется храповик. Второго определения «что есть утверждение» в
   модуле не появляется.
2. Блоки: стена рычага не противоречит замеру · эхо храповика не противоречит замеру · **два
   настоящих замера противоречат по-прежнему** (иначе сторож просто выключен).
3. Мутации на каждую половину.

## Долг, названный отдельно и НЕ закрываемый этой починкой

28 строк документа несут напряжение, поставленное храповиком поверх спуска, остановленного нашим
рычагом. Их числа не ложны, но и не их: происхождение размыто. Метод владельца перепишет их
измерением по мере прохода диапазона. **Трогать 28 строк его хранилища улик в одиночку я не буду** —
это отдельная работа с отдельным разбором.

## ✅ STATUS: DONE (2026-08-23 11:1x +03:00)

**Починено одной строкой в `firstInversion`:** в сравнение попадают только строки, которые своё
напряжение ТРЕБУЮТ (`demandsVoltage`) — тот же предикат, которым с 2026-08-22 пользуется храповик.
Второго определения «что есть утверждение» в модуле не появилось.

**Доказано красным.** Блоки: «СТЕНА РЫЧАГА НЕ ПРОТИВОРЕЧИТ ЗАМЕРУ» · «ЭХО ХРАПОВИКА НЕ ПРОТИВОРЕЧИТ
ЗАМЕРУ» · «ДВА НАСТОЯЩИХ ЗАМЕРА ПРОТИВОРЕЧАТ ПО-ПРЕЖНЕМУ». Мутация DH (вернуть сравнение по
`isUnmeasured`) красит первые два; DJ (выключить сторож вовсе) красит три блока, включая третий —
то есть правка не «сняла сторож», и это проверено отдельно.

⚠️ **Первая редакция двух блоков покраснела по МОЕЙ ошибке:** `ok` в этом наборе двухаргументный
`(имя, условие)`, а я передал `(имя, длина, 0)` по сигнатуре соседних наборов — длина 0 читается как
ложь. Файл предупреждает об этой ловушке своим же комментарием. Записано здесь, потому что класс
повторяется.

**Наблюдение:** `npm run curve -- --verify` на боевом документе — 127 ступеней сверено, расхождений
нет. Батарея 18 наборов / 1000 зелёных блоков.
