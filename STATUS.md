## Восемь фактов, определяющих все решения

1. **Потолок мощности двигается только 250 → 300 Вт** — 50 Вт запаса. Цели PDF (−60…−120 Вт) одним
   ограничением мощности недостижимы; правка кривой обязательна.
2. **`nvidia-smi -pl` здесь пишет — проверено** (2026-08-09, с согласия владельца): 300 → 290 Вт,
   перечитано, возвращено. **Ловушка:** сообщение утилиты печатает в поле «from» значение по
   умолчанию, а не прежнее. Состояние только перечитывать (`researches/01` §5).
3. **`nvidia-smi` вообще не умеет читать напряжение** — такого поля нет. Поэтому фаза 5 *зависит*
   от моста к NVAPI из фазы 4 (`researches/03` §2).
4. **Vmin зависит от программы на ~100 мВ**, отказ у края — обрыв, а не склон. Один бенчмарк не
   доказывает ничего; запас не опционален.
5. **Больше половины отказов от андервольта — молчаливые.** «Не упало» не является приёмкой.
6. **Сетка ЧАСТОТ измерена, сетка НАПРЯЖЕНИЙ — нет.** Лестница: 5 ступеней памяти, все четыре полные
   дают **одинаковые 389 точек 180…3090 МГц**, шаг чередуется 7 и 8 МГц. Значит фаза 5 разворачивает
   частоту один раз. Шаг напряжения (6,25 мВ в `config`) помечен НЕИЗМЕРЕННЫМ — долг фазы 4.
7. **HWiNFO64 выведен из архитектуры** — стороннее GUI (запрет `GOAL.md`), а датчик горячей точки на
   RTX 50 отключён драйвером; эта карта возвращает `N/A`.
8. **Нагрузки идут «процесс на прогон»** — запуск (~140 мс) сильно больше ядра (0–25 мс), поэтому
   карта выходит лишь на 20–30 %. Форма переходной нагрузки верная, насыщение — нет. **Фазе 5 нужна
   нагрузка, крутящаяся внутри себя N секунд.**

## Эстафета — что делать следующей сессии, по шагам

Ты стартуешь с пустым контекстом. Ниже всё, чтобы стать полезным за десять минут.

1. **Проверить среду одной командой:**
   ```
   npm run phase1:accept      # ждём: 14 файлов 0 провалов · манифест сходится · фикстуры 5/5 ·
                              #       самопроверка 10/10 · P1-AC5 без штампа 0 · расшифровка сходится
   npm run gpu:info           # ждём: драйвер 610.88, VBIOS 98.03.58.40.8b, 250–300 Вт, 3090 МГц
   ```
   **Если драйвер изменился с 610.88 — каждый эталон и каждая контрольная сумма недействительны до
   перепроверки.** Это правило R6. `--verify-baseline` скажет об этом сам; пересъёмка —
   `npm run stress -- --capture-baseline`.
   **На свежем клоне эталона НЕТ** (`runs/` под gitignore) — вердикт будет НЕИЗВЕСТНО, пока не
   снимешь. Отгружаемая копия той же правды — `workloads/MANIFEST.json`.

2. **Прочитать по порядку:** этот файл → `plans/01_EPIC_kago_orchestrator.md` (вся форма разом,
   по-русски) → `researches/01` §5 (что именно умеет `nvidia-smi` и где он врёт). `researches/01`,
   `02`, `03` — доказательная база: **читать, не выводить заново.**

3. **Взять фазу 2 — но первым делом её СПЛАНИРОВАТЬ.** Операционного плана у неё ещё нет
   (по лестнице планирования план фазы N+1 пишется, когда закрыта фаза N). Значит:
   `/plan-task` или `/plan-epic` → `plans/03_epic01_phase2_silent_cold.md`, цитируя якоря из
   `plans/01_EPIC` §3. Перед каждым шагом кода цитировать якорную строку плана.

4. **🔴 ФАЗА 2 ПЕРВАЯ ПИШЕТ В GPU. Прочитай это до первой команды.**
   - Файл прав (`.claude/settings.local.json`, под gitignore) заставляет каждый вызов
     `-pl`/`-lgc`/`-rgc` спрашивать владельца — это сторож, рождённый инцидентом 2026-08-09
     (`EXPERIENCE.md` → EXP-0005). Не обходить.
   - **Согласие владельца покрывает только `-pl`.** На `-lgc` согласия НЕТ — завести интервью и
     спросить ДО первой записи.
   - **У каждой записи парный откат в том же модуле** (правило R5) и **чтение назад после записи**:
     не совпало — профиль отвергается (контур Apply, `PROJECT_ARCHITECTURE_INTERNAL_MAP.md` §5).
   - Состояние карты только ПЕРЕЧИТЫВАТЬ: `nvidia-smi` в поле «from» печатает значение по умолчанию,
     а не прежнее (факт 2 выше).

5. **Нужно слово владельца — не спрашивай в чате.** Заведи интервью и подними контур:

   по объявленным целям, и только потом смена статуса; сторож проверяет оба плеча: `npm run questions`.

6. **Любая новая проверка доказывается КРАСНЫМ до того, как ей верят.** Против предыдущей версии:
   `git archive HEAD <каталог> | tar -x -C <врем.папка>`, туда же новый файл проверок, прогнать.

   которого нет (досье среды).

7. **Мелочи, которые экономят час:** редактор светит красным в `.cu` — его C++-анализатор не знает

## Состояние машины, о котором надо знать

- **`nvcc` требует загруженной среды MSVC** — сам он хост-компилятор не находит. `toolchain.mjs`
  ищет его через `vswhere`; кросс-компилятор с x86-хостом проверен как запасной путь.
- **`/tmp` — не один путь.** У bash он есть (монтирование MSYS2), у Node из того же bash — `D:\tmp`,
  которого нет. Для временных файлов брать scratchpad сессии.
- **Grep локализует, Read проверяет** (EXP-0007), а **Read показывает NUL-байты пробелами**
  (EXP-0010). Полный список повадок машины — досье среды в `AGENT_GUIDE.md`.
- **`.claude/settings.local.json`** — грант прав агенту от владельца, под gitignore. **2026-08-10
  расширен до записи в GPU:** `-pl`, `-lgc`, `-rgc` в обеих оболочках, плюс `schtasks /create` и
  `Set-ItemProperty` (инструменты фазы 3). Механического тормоза на этих вызовах больше нет —
  тормозом остаётся правило машины владельца в `AGENT_GUIDE.md`.
- **Автозагрузка LosslessScaling и NVIDIA Broadcast выключена 2026-08-10** по слову владельца
  («убери из автозагрузки»). Сделано штатным механизмом диспетчера задач — флаг `03` в
  `HKCU:\...\Explorer\StartupApproved\Run`; **строки запуска в `Run` не тронуты**, поэтому откат это
  возврат байтов в `02...` или галочка в диспетчере. Имя значения у Broadcast несёт **хвостовой
  пробел** (`NVIDIA Broadcast `) — без него правка молча создаст вторую запись.
- **Фон на карте — это не пустяк, а помеха замеру.** На машине живут Chrome, VS Code, Docker
  Desktop, Parsec, NordVPN, PotPlayer, NVIDIA Overlay, LG Hub: в покое карта сидит не на 180 МГц, а
  около 825. Владелец разрешил: *«при измерениях всё, что создаёт фоновую нагрузку — останавливай»* —
  границы и обязательный подъём обратно описаны в `AGENT_GUIDE.md`.
