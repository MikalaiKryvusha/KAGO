## Что это значит (разбор агента)

**Сильная модель планирует и судит, слабая — исполняет по рельсам.** Беклог проекта нарезается в
операционные планы такой детальности, чтобы модель, сильная в строгом следовании плану, могла
закрывать шаги без догадок и без решений уровня владельца.

## Что делает план «лёгким для слабой модели» (критерии нарезки)

Опора — уже оплаченные уроки этого проекта:

1. **Шаг атомарен**: один файл или одна команда за шаг; результат шага наблюдаем (вывод назван).
2. **Команды — готовыми строками, не описаниями.** Слабая сессия исполняет вставленную команду
   и игнорирует эссе (правило Repro-строки в `EXPERIENCE.md`).
3. **Ожидаемый вывод написан рядом с командой** («ждём: 31 файл, 0 провалов») — сверка вместо
   интерпретации.
4. **Критерии приёмки по `REQUIREMENTS_FRAMEWORK.md`**: Scale · Meter · Target, без стоп-слов.
5. **Стоп-правила выписаны в сам план**: 3 неудачные попытки → стоп и доклад (не «копать глубже»);
   всё, что пишет в карту — ТОЛЬКО при владельце (правило `bugs/03`); чего не трогать — названо
   явно (границы шага).
6. **Ноль решений владельца внутри шага**: развилка уровня видения = стоп-точка плана, а не выбор
   исполнителя (три двери, `PHILOSOPHY.md`).
