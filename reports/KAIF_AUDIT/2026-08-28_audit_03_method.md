## 1. Ответ одной страницей

Ваш вопрос: проект выглядел простым на два вечера, идёт три недели, агенты наступают на грабли и
переделывают движок — есть ли методологическая проблема в постановке работ и векторах цели?

**Три ответа, все три верны одновременно.**

**Первый: заказ не был «на два вечера» — и это не оправдание, а замер.** Двухвечерняя версия этой
задачи существует — MSI Afterburner, ручной подбор, проверка глазом, — и вы сами запретили её первой
же строкой `GOAL.md` (без сторонних GUI, свой код). Заказана была строгая версия: автономный
оркестратор с собственным мостом к NVAPI и доказуемой стабильностью. У строгой версии жестокая
физика: **12 смертей машины за проект** (`researches/15`), карта не исполняет заказ (2197 → 2205 МГц),
таблица V/F едет на 15–30 МГц с нагревом, а край по построению ищется ЧЕРЕЗ отказ. Честный масштаб
такого заказа — недели, не вечера.

**Второй: из этих недель заметная часть куплена не продуктом.** Числа: **65 % всех багов (44 из
68) — дефекты самой защитно-проверочной машинерии**, а не тюнинга и не железа; из 42 багов, стоивших
или блокировавших живой вечер, **25 — машинерия**: леса съели больше времени живой карты, чем код,
который они охраняют. 38 % коммитов (182 из 476) трогают только документы. Документная масса —
83 598 строк против 50 252 строк кода против **11 найденных краёв из 389**.

**Третий — и это ответ на ваш вопрос про векторы цели: методологическая проблема существует, она
одна, и у неё пять лиц.** Векторы цели у сессий выстроены честно — по канону. Но **в каноне нет
глобального вектора: ни один инструмент фреймворка не спрашивает, приблизила ли работа приёмку.**
Судья проверяет честность заявлений, тесты — корректность кода, сторожа — безопасность записи;
расстояние до вашего критерия («края для всех 389 частот, четыре режима на ярлыках») не считает
никто. Поэтому каждая сессия оптимизирует последнюю боль — и делает это добросовестно, дорого и в
сторону от финиша. Агенты делали ровно то, что система вознаграждает. Лечится это не «стараться
лучше», а одним счётчиком и пятью правилами (§6).

## 4. Пять лиц одной проблемы

### Д1. Вектор цели сессии направлен на последнюю боль, а не на приёмку

Каждый живой инцидент порождает эпик; эпики выстроились цепочкой (36 → 41 → 42 → 43 → 47 → 50 → 51 —
девять переделок движка за две недели), и у каждого триггер — **последнее** событие: слово, баг,
смерть машины. При этом:

- **эпик 42 (гибкий тюнинг)** — единственный, чей критерий приёмки совпадает с вашим (F-AC8:
  «389 из 389»), — разблокирован вами вечером 24.08 за один час (интервью 014 закрыто в 22:54) и
  **не начат по сей день**; его шапка до сих пор утверждает «ждёт ответов владельца» — при закрытом
  интервью (класс «двух правд», `bugs/25`);
- **`plans/21` (прожиг полного конверта)** — прошлый аудит назвал его «критический путь ЛЮБОГО
  отгружаемого режима» — код не начат и спустя неделю;
- **механизм интерполяции/экстраполяции** — ваш способ закрыть ~300 непрожигаемых строк, узаконенный
  вами 24.08, — «тега нет, механизма нет» (`GOAL.md`), и плана на него нет.

Ни одна сессия не открывается вопросом «сколько краёв закрыто и что сегодня двинет число». Прошлый
аудит предписал «покупать продукт, а не леса» **прозой** — за следующую неделю открылись три
машинных эпика. Предписание без носителя не удержалось (ровно класс, уже описанный вами в тикете
KAIF #22: правила-проза слабые модели не держат — а здесь его не удержали и сильные).

### Д2. Цена инцидента фиксированная и максимальная — независимо от тяжести

Канон требует полный пакет за каждый дефект: баг-документ + сторож, доказанный красным + мутации +
близнецы + урок + правило. Тяжесть не различается — и 68 дефектов получили 68 похорон первого
разряда, хотя настоящих убийц (карта, машина, данные, доверие) среди них меньше трети. Следствия:

- **леса рождают собственные баги и оплачивают их из общего времени**: 44 машинных дефекта из 68,
  среди них — сторож пульса убил писателя, которого охранял (`bugs/19`); уборочный крюк убил живую
  развёртку (`bugs/21`); безопасный режим невозможно снять (`bugs/51`); два ВЕРНЫХ правила отменили
  друг друга (EXP-0104); сторож противоречий краснел на штатном состоянии (EXP-0076); сторожу
  вопросов перестали верить по ложному диагнозу (`bugs/40`);
- открытых багов при этом **29** — хвост не сходится, потому что закрытие каждого стоит столько же,
  сколько закрытие настоящего убийцы;
- офлайн-батарея (1 404 блока) поймала **13 %** новых дефектов; ваш глаз и живой прогон — **60 %**.
  Самый дорогой прибор проекта — ваше присутствие — работает детектором дефектов лесов.

### Д3. Канон растёт монотонно и съел контекст сессий

Ядро перечитывания — 5,8 тыс. строк за проход, ежечасно; STATUS — 1 322 строки при ориентире 200
(долг признан в нём самом); GOAL — 1 514 строк стенограммы со слоями отмен («не перепутай два числа
885»); молитва продублирована в 8 файлов и произносится вслух перед каждой задачей (у неё есть
собственная самопроверка на 6 блоков). Растёт канон только в одну сторону: новое нарушение → новое
правило → канон длиннее → хуже удержание в контексте → новое нарушение. Симптом того, что порог
пройден: **корпус больше не удерживается в согласии силами тех сессий, которым он адресован** —
«две правды» (`bugs/25`) возвращаются (свежий пример — шапка эпика 42). Даже этот аудит не смог
прочитать три канонских документа за один проход инструмента чтения — они превышают его лимит.

### Д4. Дефицитный ресурс — живая карта при вас — не управлялся как дефицитный

Продукт двигают только живые прогоны; их окно — ваш вечер. Из 35 сессий с живым контактом **10
сорваны нашими дефектами и только 3 — картой**. Ваши слова в хронологии: «с самого утра… так и не
дошли» (S28), «0 из 27» (S48). Предполётная дисциплина (одна команда проверки готовности, репетиция
точной команды на стенде накануне) появилась только в эпике 43 фазы 3 — на 17-й день. Неограниченный
ресурс (офлайн-часы) тратился щедро, ограниченный (ваши вечера) — не считался.

### Д5. Скоуп рос без ценника — и «два вечера» никогда не сверялись с книгой заказов

Каждое ваше слово канонизируется дословно и становится обязательством: два профиля → четыре режима;
окно наблюдения + звук + тема + переключатель языков; логотип; голосовой контур; облако тегов;
визуализатор кривой; молитва; регистр языка. **Каждое добавление законно — сумму не показал никто.**
Фреймворк фиксирует слово, но не его цену; ваша же формула «снижаем, пока цена ≤ N» к самому проекту
ни разу не применялась. Сюда же — качели управления, канонизированные с равной силой в обе стороны:
«чини явные блокеры, срать на леса» (S3) и «сначала мы пишем планы, а затем имплементацию» (S51),
«Здание важнее лесов» (24.08) и «подними принципы до молитвы перед каждой работой» (24.08, тот же
день). Оба направления верны по своему поводу — но маятник, канонизированный в обе стороны без
ценника, оплачивается сессиями.

## 5. Что методология делает правильно — не сломать при лечении

1. **Знание переживает катастрофы:** журнал упреждающей записи с `fsync` назвал убившую ступень
   после настоящего BSOD; 12 смертей машины не стёрли ни одного факта.
2. **Ни один инцидент не прошёл сквозь стоящий сторож** — инциденты случались там, где сторожа ещё
   не было (подтверждено обоими прошлыми аудитами).
3. **Ваше слово исполняется быстро и точно:** переанкеровка запаса — в тот же час; пять развилок
   интервью 014 — за вечер; контур согласований работает.
4. **Честность отчётов:** «ЗАДАЧА ДНЯ НЕ ВЫПОЛНЕНА» заголовком; STATUS не приукрашивает.
5. **Виртуальный стенд окупился:** репетиция 121 частоты за 5:45 без касания карты; ловушки гоняют
   настоящий движок.
6. **Свежие планы образцовы по форме** (42, 52: цитата → вектор → критерии «шкала·прибор·цель» →
   измеренная база). Проблема не в качестве артефактов — в их портфеле.

## 6. Рецепт: один счётчик, пять правил, один мораторий

**Счётчик (Р1). Приёмка — единственный общий счёт.** Каждая сессия открывается и закрывается
строкой: **«краёв: X/389 (измерено · соседкой · выведено) · режимов: Y/4 · что сегодня двинуло
число»**. Механика — `npm run curve -- --progress` (тикет `ideas/14`, полчаса работы). Сессия, не
двинувшая число и не разблокировавшая ближайший живой прогон, обязана назвать почему — одной
строкой, вслух.

**Р2. Пропорциональная церемония.** Тяжесть 1 — пострадали карта/машина/данные/ваше доверие → полный
пакет как сегодня. Тяжесть 2 — потерян прогон или час → баг-документ + сторож, без эпика. Тяжесть
3 — прочее → одна строка в EXPERIENCE. **Инцидент сам по себе эпика не открывает** — эпик проходит
через Р1.

**Р3. Диета канона.** STATUS ≤ 400 строк механическим советчиком в `npm run check`; GOAL расщепить
на оперативный «ЗАКАЗ» (~150 строк действующих определений, утверждаете вы) и дословный архив;
урок, ставший механическим сторожем, сворачивается до строки со ссылкой; молитва — каденция на ваш
выбор (развилка Q2). Ничего не удаляется — разделяется оперативное и архивное.

**Р4. Живой прогон — первоклассный ресурс.** Предполёт одной командой до того, как вы сели за
машину; точная команда вечера репетируется на стенде накануне; прогон, сорванный нашим дефектом, —
тяжесть 2 минимум; после живой приёмки сторожа смерти (эпик 51) — развилка о ночных развёртках (Q4).

**Р5. Прайс на входе.** Новое пожелание получает ярлык цены («стоит N вечеров/сессий, подвинет в
очереди Z») ДО канонизации — и решение с ценой на руках принимаете вы. Это ваша же формула
оптимизации, применённая к проекту.

**Мораторий:** до «краёв ≥ 195/389 (50 %)» новые контуры машинерии не открываются — кроме блокеров
ближайшего живого прогона (развилка Q1; порог назначаете вы).

## 8. Остаток пути — честная оценка с названными входами

Входы (все измерены): 389 частот обслуживаются ~75 группами напряжения (5,19 частоты на группу,
замер 15.08); прожиг — одна форма 10 с (`plans/50`, снято 26.08); темп лучших вечеров — +18 строк
(25.08) и +7 краёв из скобок журнала без единого прожига (26.08); верх диапазона прожигам не
даётся — закрывается выводом (ваше слово 24.08); низ — закреплением (механизм стоит с эпика 43).

**При принятии Р1–Р5 и моратория:** середина диапазона краями — 3–5 живых вечеров; вывод модели на
верх/низ — 1–2 офлайн-сессии; квалификация режимов — `plans/21` + 2 вечера игры. **Итого порядка
двух недель календаря до «краёв 389/389 + четыре работающих ярлыка».** Это арифметика от названных
входов, не обещание; главный риск — новые классы отказов у края, их цена уже ограничена журналом и
сторожем смерти.

## Приложение А. Руководство агенту: правило критического пути (готовая врезка в AGENT_GUIDE.md — ждёт вашего «да»)

*(английский — язык исполнителя; врезается после раздела «Task execution discipline»)*

### The critical path rule — the acceptance criterion is the only shared score

1. **Open and close every session with the delivery line:** `edges: X/389 (measured · inherited ·
   derived) · modes shipped: Y/4 · what moved today: <one line>`. Print it from
   `npm run curve -- --progress`; until that command exists, read `curves/measured.json`. A session
   that moves nothing and unblocks no upcoming live run must say why, in one line, out loud.
2. **Pick work by one question:** does this move the acceptance number, or unblock the NEXT live
   run? If neither — it waits for the owner's explicit word. The newest pain is not a priority
   claim; the queue in the method audit §7 is.
3. **Severity ladder for incidents.** S1 — the card, the machine, measured data or the owner's
   trust was harmed → the full package (bug doc + guard proven red + mutations + lesson + twins).
   S2 — a run or an hour was lost → bug doc + guard, no epic. S3 — everything else → one
   EXPERIENCE line. **An incident never opens an epic by itself** — an epic must pass rule 2.
4. **Live evenings are the scarcest resource in the project.** Preflight by one command before the
   owner sits down; rehearse the exact evening command on the bench beforehand; a run aborted by
   our own defect is S2 minimum and its bug doc opens with the cost line («cost: one owner
   evening»).
5. **The map is not the product.** STATUS within its budget; a lesson that became a mechanical
   guard collapses to one line + pointer; a new canon section needs the owner's yes AND a named
   cost in sessions.
6. **Scope carries a price tag.** When the owner asks for something new, answer with the work AND
   its cost in evenings/sessions and what it displaces in the queue — the owner's own formula
   («reduce while the price ≤ N») applied to the project itself. The owner decides with the price
   in hand; deciding FOR the owner by silently absorbing scope is the defect, not the courtesy.
